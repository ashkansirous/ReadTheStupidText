# CLAUDE.md — tools/desktop-vm

Rules for the Hyper-V VM desktop test scripts.

- Scripts written with the Write tool can get a backslash-r sequence (the two characters backslash and r inside a string) turned into a literal CR byte; check the bytes of any `tools/desktop-vm/*.ps1` you write. (Slice 163: docs/plan/slices/163-desktop-tests-in-hyperv-vm.md)
- Never leave Windows Update on in `clean` (its "install updates" prompt stalls every run), and never wait on a VM screen nobody can answer: a wait with no progress for `-StallMin` takes a screenshot (`Save-VmScreenshot`) and throws `stalled: ...; screen: <png>`. (docs/plan/notes/2026-10-28-desktop-vm-updated-image.md)
- The MSIX under test is found by build key (`Build-TestPackage.ps1`, `<worktrees>/_builds/`), never as "the newest file under `pkgs`"; the build takes no VM lock (only install and checks hold the VM). `-App auto` runs only the touched apps (`tools/test-targets.ps1`). (Slice 180: docs/plan/slices/180-faster-device-tests.md)
- Monthly refresh is `New-TestVm.ps1 -UpdateOnly` (restores `clean`, updates, swaps the checkpoint, never leaves the VM without a `clean`); `-Force` only when the licence runs out or the VM is damaged. (docs/plan/notes/2026-10-28-desktop-vm-updated-image.md)
- `dino-settings` passes the real grown-up gate with `Invoke-GateHold` (see the gate-hold rule below): the mouse (not touch) holds the ring found by its exact name "Press and hold for 3 seconds" (the label above it has a full stop and would match a partial lookup); never add a gate bypass. Flow: "For grown-ups" button, gate, the corner, its Settings tab; a Settings sub-page's back arrow is a tappable Border named "Back", not a Button. Use `Find-UiaExact`, not the partial `Find-UiaByName`, for such lookups. If injection proves flaky in three runs, fall back to the gate's screen-reader alternative (`ShowHoldAlternative`), never a skip. (Slice 188: docs/plan/slices/188-dino-settings-vm-check.md)
- Run the VM scripts with PowerShell 7 (`pwsh -NoProfile -File ...`), never `powershell.exe` 5.1 from Bash: under 5.1 they failed with "failed to load ConvertTo-SecureString" three times on 2026-10-31 (cause not proven). (Note: docs/plan/notes/2026-10-31-1000-feedback-loop-w1.md)
- The VM screen is 1024 x 768, so window-size checks clamp their expectations to its work area. The Release VM build shows no `Debug.WriteLine`, so a Windows-head check needs a file trace it can read back (`window-trace.log` in the app data folder). (Slice 235: docs/plan/slices/235-dino-windows-window.md)
- `Invoke-DesktopTest.ps1` dry-runs the selected checks on the host before the VM starts (`_dryrun.ps1`, `DRYRUN` lines; self-test `test-check-dryrun.ps1`): FAIL (stops the run, exit 1) for a width/height constant larger than the 1024 x 768 guest in a file that never clamps to `Get-WorkArea`/`WorkingArea` or sets a resolution, a hand-written `FindFirst`/`FindAll` by `NameProperty` (use `Find-UiaExact`), a parse error, or a process name that is not the built package's executable (read from the MSIX manifest); WARN for `Start-Sleep` of 3 s or more without a `# fixed-wait: <why>` comment on the line (poll with `Wait-Until` instead). A new check is run through it by `-Check <name>` as usual. (Slice 253 item 3)
- `Find-UiaByName` prefers an exact name and skips tooltips and their children: WinUI tooltips sit in the UIA tree ahead of the control, so a partial match taps the popup. A keyboard check polls `window-trace.log` for each key's line instead of sleeping a fixed time (Right took 2.2-2.6 s after Space), and sends arrow keys as extended keys. (Slice 235: docs/plan/slices/235-dino-windows-window.md)
- `Cursor.Position` alone raises no WinUI pointer move in the VM; send `mouse_event` `MOUSEEVENTF_MOVE`. `-Check <name>` runs only `dino-launch` then the named check, so `dino-desktop-polish` needs the full set. (Slice 235: docs/plan/slices/235-dino-windows-window.md)
- A failed check or harness error copies the guest's crash evidence (`events.txt`, `wer\`, `trace-tail-*.txt`) to `<CopyOut>\crash-evidence` or `<VmRoot>\crash-evidence\`; read it before guessing at a crash. Self-test `test-crash-evidence.ps1`. (Slice 259: docs/plan/slices/259-night-2026-11-03-2349-leftovers.md)
- A VM check declares its prerequisite in a `# after: <check>` header that `-Check` reads (chains are followed, prerequisites first, so `-Check dino-reorder` runs `dino-onboarding-keys`, `dino-onboarding`, `dino-launch`, then itself; a loop throws; Slice 393 item 13); `_dryrun.ps1` (self-test `test-check-dryrun.ps1`, in `tools-selftests.yml`) fails a check whose single-quoted trace string is not in `src\`; hover and drag checks move the pointer with `Move-MouseTo` (`checks/_lib.ps1`, real `mouse_event`), never `Cursor.Position`. (Slice 269: docs/plan/slices/269-feedback-loop-2026-11-04-1441-leftovers.md)
- `dino-onboarding-keys` is the first Dino check: it needs the fresh first-run app and walks it with the keyboard (story languages and book picker Space/Enter, listen Space/Enter/Esc, voice Enter/Esc), leaving the app on the voice step; `dino-onboarding` (`# after: dino-onboarding-keys`) finishes the first run, and `dino-launch` (`# after: dino-onboarding`) then finds the shelf. `-Check <name>` always runs `dino-onboarding-keys` first, then the check's `# after:` prerequisites and the check; on a guest whose first run is already done `dino-onboarding-keys` fails at once ("first run already done, key walk not run"), so it never reports a pass for a walk it skipped; the harness restores the clean checkpoint, so a normal run always starts fresh. `dino-onboarding-skip` (`# after: dino-onboarding-keys`) is the other route through the first run ("Skip this step" on the voice intro, locked shelf, no recording): a separate run, `-Check dino-onboarding-skip`, never in the default list and never after `dino-onboarding` (Slice 418). (Slice 325: docs/plan/slices/325-dino-2026-11-08-redesign.md)
- A check that opens the Dino grown-up gate holds it with `Invoke-GateHold` in `tools/desktop-vm/checks/_lib.ps1`, never a bare mouse down/up: the VM's synthetic mouse sometimes delivers the release about 7 ms after the press, so the helper retries up to 3 times and logs each retry. (Slice 325: docs/plan/slices/325-dino-2026-11-08-redesign.md)
- Release Dino VM test packages (`DINO_TEST_BOOKS`) write no `[Purchases]` markers: `FakePurchases.WriteMarker` is `#if DEBUG` and Windows has no `TestHookLog` sink; a VM check must not expect them. (Slice 353: docs/plan/slices/353-ci-sdk-pin-and-vm-test-package.md)
- `dino-record`: the key-R stage needs the app's "Dino keyboard: R used" trace line AND either the Stop button or a microphone alert ("Microphone is off" / "The recording didn't work..."), since either proves the key reached the page; it fails when neither shows (a consent prompt holding focus). The clean image has no microphone decision, so Windows asks on the first R (a `PickerHost` window "Let Dino: Kids Books & Stories access your microphone?"); in a full run `dino-onboarding` denies it first (`Answer-MicConsentPrompt`, `checks/_lib.ps1`, Slice 418), so `dino-record` then takes its "no prompt" path. A registry Deny under `CapabilityAccessManager\ConsentStore\microphone` is NOT honoured for the MSIX app (VM run 2026-11-08), so never use it. The prompt is NOT reachable from the UIA root (no `Shell_SystemDialog` among the root's children; FindWindow and FindAll on the dialog find nothing, VM run 2026-11-08): it is reachable only as `AutomationElement.FocusedElement` after R, a Button (`No`, AutomationId `Button0`, process `PickerHost`) whose RawView ancestor is a Window of class `Shell_SystemDialog` named "Let Dino: Kids Books & Stories access your microphone?". After R the stage polls the focused element for up to 20 s; when it is a Button outside DinoReader.App under that dialog it invokes it (InvokePattern) if its Name is `No` / `Don't allow` / `Deny` / `Block`, else walks the dialog's buttons with RawViewWalker for one that is, then expects the app's "Microphone is off" alert (shown within 10 s of the No: the app is right); with no prompt it expects the alert or the Stop button. It logs which path it took, and a prompt with no deny button fails naming the buttons it saw (Slice 319: docs/plan/slices/319-device-run-2026-11-08-fixes.md; Slice 320 item 8). The alert is dismissed after matching. The alerts have no AutomationId and are matched by their English text, so the VM must run in English. (Slice 284)
- `dino-store-shots` (opt-in, `# after: dino-onboarding-skip`, no network: the VM is offline by design) makes the Microsoft Store shots and the landscape footage: the guest display is set to exactly 1920 x 1080 (`Set-ScreenResolution`; the VM's video adapter tops out at 1920 x 1200, so no larger mode exists; the return code and, on a refusal, the offered modes are logged), the `fullscreen` hook (`fullscreen.request`, same pattern as `full-shelf`) puts the Dino window in the `AppWindowPresenterKind.FullScreen` presenter so its client area is the whole display, and `Save-ClientScreenshot` captures that area only and throws unless it is exactly 1920 x 1080. The 12-book shelf comes from the `full-shelf` hook, started in the Release test package by dropping `full-shelf.request` into `LocalState` (`Platforms/Windows/FullShelfRequest.cs`; outcome `HOOK full-shelf ok|failed|fault` in `window-trace.log`); the hook imports all eight added books from packages (no download), so it needs `-WithShelfPackages <folder made by .github/scripts/fetch-shelf-packages.mjs <folder> --include-free>`; shot 06's Store tab lists the shelf books with the live list's ages and sale state (`shelf-listing.json` from the same fetch script; `TestStore.ShelfEntryOf`): a paid book shows a price tag (the list carries none; the pretend store's `£0.99` is the mock's), a free one "Free". Footage frames (`footage-<clip>-<nnnn>.png`, 10 per second) stay in the results folder; the runner's `-CopyOut` copies the shots and encodes each clip to `<clip>.mp4` with ffmpeg (which must be on the host PATH), then deletes the frames. (Slice 434: docs/plan/slices/434-dino-windows-store-shots-and-landscape-video.md)
- The Hyper-V VM display maxes out at 1920 x 1200 (Default), so a framed 1920 x 1080 window is impossible: store shots use full screen at 1920 x 1080 plus the test zoom hook. (Slice 434: docs/plan/slices/434-dino-windows-store-shots-and-landscape-video.md)
- `ReadingSurface` is not exposed to UIA; wait on the visible title instead. (Slice 434: docs/plan/slices/434-dino-windows-store-shots-and-landscape-video.md)
