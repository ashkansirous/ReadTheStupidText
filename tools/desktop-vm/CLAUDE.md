# CLAUDE.md — tools/desktop-vm

Rules for the Hyper-V VM desktop test scripts.

- Scripts written with the Write tool can get a backslash-r sequence (the two characters backslash and r inside a string) turned into a literal CR byte; check the bytes of any `tools/desktop-vm/*.ps1` you write. (Slice 163: docs/plan/slices/163-desktop-tests-in-hyperv-vm.md)
- Never leave Windows Update on in `clean` (its "install updates" prompt stalls every run), and never wait on a VM screen nobody can answer: a wait with no progress for `-StallMin` takes a screenshot (`Save-VmScreenshot`) and throws `stalled: ...; screen: <png>`. (docs/plan/notes/2026-10-28-desktop-vm-updated-image.md)
- The MSIX under test is found by build key (`Build-TestPackage.ps1`, `<worktrees>/_builds/`), never as "the newest file under `pkgs`"; the build takes no VM lock (only install and checks hold the VM). `-App auto` runs only the touched apps (`tools/test-targets.ps1`). (Slice 180: docs/plan/slices/180-faster-device-tests.md)
- Monthly refresh is `New-TestVm.ps1 -UpdateOnly` (restores `clean`, updates, swaps the checkpoint, never leaves the VM without a `clean`); `-Force` only when the licence runs out or the VM is damaged. (docs/plan/notes/2026-10-28-desktop-vm-updated-image.md)
- `dino-settings` passes the real grown-up gate: `Invoke-PressAndHold` (`checks/_lib.ps1`) holds the mouse (not touch) on the ring for 3.5 s, found by its exact name "Press and hold for 3 seconds" (the label above it has a full stop and would match a partial lookup); never add a gate bypass. Flow is Slice 189's: "For grown-ups" button, gate, grown-up mode, gear, Settings; the Settings Back is a tappable Border named "Back", not a Button. Use `Find-UiaExact`, not the partial `Find-UiaByName`, for such lookups. If injection proves flaky in three runs, fall back to the gate's screen-reader alternative (`ShowHoldAlternative`), never a skip. (Slice 188: docs/plan/slices/188-dino-settings-vm-check.md)
- Run the VM scripts with PowerShell 7 (`pwsh -NoProfile -File ...`), never `powershell.exe` 5.1 from Bash: under 5.1 they failed with "failed to load ConvertTo-SecureString" three times on 2026-10-31 (cause not proven). (Note: docs/plan/notes/2026-10-31-1000-feedback-loop-w1.md)
- The VM screen is 1024 x 768, so window-size checks clamp their expectations to its work area. The Release VM build shows no `Debug.WriteLine`, so a Windows-head check needs a file trace it can read back (`window-trace.log` in the app data folder). (Slice 235: docs/plan/slices/235-dino-windows-window.md)
- `Invoke-DesktopTest.ps1` dry-runs the selected checks on the host before the VM starts (`_dryrun.ps1`, `DRYRUN` lines; self-test `test-check-dryrun.ps1`): FAIL (stops the run, exit 1) for a width/height constant larger than the 1024 x 768 guest in a file that never clamps to `Get-WorkArea`/`WorkingArea` or sets a resolution, a hand-written `FindFirst`/`FindAll` by `NameProperty` (use `Find-UiaExact`), a parse error, or a process name that is not the built package's executable (read from the MSIX manifest); WARN for `Start-Sleep` of 3 s or more without a `# fixed-wait: <why>` comment on the line (poll with `Wait-Until` instead). A new check is run through it by `-Check <name>` as usual. (Slice 253 item 3)
- `Find-UiaByName` prefers an exact name and skips tooltips and their children: WinUI tooltips sit in the UIA tree ahead of the control, so a partial match taps the popup. A keyboard check polls `window-trace.log` for each key's line instead of sleeping a fixed time (Right took 2.2-2.6 s after Space), and sends arrow keys as extended keys. (Slice 235: docs/plan/slices/235-dino-windows-window.md)
- `Cursor.Position` alone raises no WinUI pointer move in the VM; send `mouse_event` `MOUSEEVENTF_MOVE`. `-Check <name>` runs only `dino-launch` then the named check, so `dino-desktop-polish` needs the full set. (Slice 235: docs/plan/slices/235-dino-windows-window.md)
- A failed check or harness error copies the guest's crash evidence (`events.txt`, `wer\`, `trace-tail-*.txt`) to `<CopyOut>\crash-evidence` or `<VmRoot>\crash-evidence\`; read it before guessing at a crash. Self-test `test-crash-evidence.ps1`. (Slice 259: docs/plan/slices/259-night-2026-11-03-2349-leftovers.md)
- A VM check declares its prerequisite in a `# after: <check>` header that `-Check` reads (one level only, no chains); `_dryrun.ps1` (self-test `test-check-dryrun.ps1`, in `tools-selftests.yml`) fails a check whose single-quoted trace string is not in `src\`; hover and drag checks move the pointer with `Move-MouseTo` (`checks/_lib.ps1`, real `mouse_event`), never `Cursor.Position`. (Slice 269: docs/plan/slices/269-feedback-loop-2026-11-04-1441-leftovers.md)
- `dino-record`: the key-R stage needs the app's "Dino keyboard: R used" trace line AND either the Stop button or a microphone alert ("Microphone is off" / "The recording didn't work..."), since either proves the key reached the page; it fails when neither shows (a consent prompt holding focus). The clean image has no microphone decision for the package, so Windows asks on the first R (a `PickerHost` window "Let Dino Book Reader access your microphone?"). A registry Deny under `CapabilityAccessManager\ConsentStore\microphone` is NOT honoured for the MSIX app (VM run 2026-11-08), so never use it. After R the stage waits up to 10 s for the consent window (process `PickerHost`, or a top-level window named like the prompt), finds its deny button by UIA (control type Button, Name `No` / `Don't allow` / `Deny` / `Block`) and invokes it, then expects the app's "Microphone is off" alert; with no prompt it expects the alert or the Stop button. It logs which path it took, and a prompt with no deny button fails naming the buttons it saw (Slice 319: docs/plan/slices/319-device-run-2026-11-08-fixes.md). The alert is dismissed after matching. The alerts have no AutomationId and are matched by their English text, so the VM must run in English. (Slice 284)
