# CLAUDE.md — tools

Rules for the device-test tooling (`tools/emulator`, `tools/phone`, `tools/desktop-vm`; the VM scripts have their own file).

- Start device checks from `run-flows.ps1 -App auto` / `Invoke-DesktopTest.ps1 -App auto` (they test only the apps the diff touches); never drop an app it names.
- Builds are cached by input hash in `<worktrees>/_builds` and run outside the device locks; the enforced limit is one emulator running flows plus the VM (`RTST_ALLOW_TWO_EMULATORS=1` allows two emulators, never with the VM).
- Phone runs need the phone charging; for network it must be unlocked once with the `.dbg` app in the foreground.
- Unattended phone runs (nobody to unlock) need the screen lock set to None or Swipe: starting a pack download, opening a book or a Settings page needs the app visible. Ask the user before they leave. Run `tools/phone/preflight.ps1` first (NO-GO means stop and ask); take the phone with `lease.ps1 -Take -Owner <name>` and set `RTST_PHONE_OWNER` (one harness script per device at a time). Switch language and voice by hook first (Slice 209: `set-language lang=<code>` in both apps, `set-voice id=<voice id>` in RTST; `stage-book-update id=<book>` stages a Dino book update; runner checks `language`, `voice`, `book-update`; Dino `set-language` sends `voice=0` on an emulator, because the voice start crashes its Debug x86_64 build); use `tap.ps1` through Settings only where no hook covers it (`set-translate mode=on|off` in RTST sets the Review page's per-text Translate tick, runner check `translate`); never report a setting "no hook" without checking this list. On a broken dev app run `reset-dev-app.ps1 -Level auto` (it moves the packs aside and back, never deletes them), record the bug and go on, never stop the run. (2026-10-29 S21 night: docs/plan/notes/2026-10-29-s21-night-runs.md)
- Phone briefs name checks from the runner, not procedures: `tools/phone/run-checks.ps1 -App rtst -Checks cold-start,highlight,notification-text` (or `-App dino -Checks book-end`) takes the lease, starts the Debug and AOT builds in the background itself, in parallel (each `dotnet build --artifacts-path <worktree>\.artifacts\<app>-<jit|aot>`, never touching `src\*\obj`; lock per checkout and variant) (`cold-start` waits for AOT, other checks start on whichever is ready, one Debug-to-AOT swap at most; a failed build FAILs its checks; status in `<worktrees>\.phone\run-status.json`), runs preflight and setup, labels every timing `aot`/`debug`, and never downloads a voice pack (`-Prepare -App <app>` first, outside the budget; no pack skips the checks that need one as `no pack: run -Prepare first`), stops at `-Budget` minutes (default 10) and prints one table naming each skipped check. A free-text phone brief only for something no check covers; a new check is a file in `tools/phone/checks/`. (Slice 213: docs/plan/slices/213-phone-check-runner.md)
- A phone brief takes `-App` from the check's `Apps` in the `$script:Catalogue` of `tools/phone/checks/_lib.ps1`, never from the last build (Slice 220's `short-lines` is Dino: briefed as RTST, the run spent its budget building Dino), and builds that app with `run-checks.ps1 -Build -App <app>` before the timed run. The first run-checks of an unattended night passes `-Reinstall`: a dev install that run-checks did not place skips every check as `installed variant unknown` (twice on 2026-10-31). (Note: docs/plan/notes/2026-10-31-1000-feedback-loop-w1.md; runner fixes in Slice 224)
- The phone's build-only step is `tools/phone/run-checks.ps1 -Build -App rtst|dino [-Variant debug|aot]`: it builds into the shared cache and exits, so never copy the build-cache steps by hand; `install-debug.ps1 -BuildOnly` is the emulator's twin, not the phone's. A second `run-checks` with the same lease owner while the first is alive exits 4 naming the live pid (a run marker `<worktrees>/.phone/run-<phone>.json`; a dead pid is free); pass `-Force` only to take over on purpose. (Slice 221: docs/plan/slices/221-device-test-tooling-leftovers-night-1.md)
- Add `-NoBuild` (or `RTST_NO_BUILD=1`) to a timed `run-checks.ps1`: it starts no build; on a cache miss it prints `cache missed for <app> <variant>, key <k>: run -Build first`, the table (all SKIP) and `run-status.json`, and exits 8, before the lease. The run prints `runs on: <check> = <app> <variant>` first. A `building` status whose builder pid is gone (or reused by another process) reads as ended: a cached APK means go, else FAIL `builder exited without an APK`; the status file is rewritten. (Slice 224: docs/plan/slices/224-phone-runner-build-cache-gaps.md)
- Maestro is not on the PATH: it lives in `<worktrees>/.tools/maestro` (or `$env:MAESTRO_HOME`) and `run-flows.ps1` finds it there. Run flows through that script; never report "Maestro not installed" without checking that folder. (2026-10-30: Slice 201's flow was left unrun on that wrong claim.)
- Maestro flows that need a pushed file live under `.maestro/<app>/needs-file/`, so `run-flows.ps1` skips them; run them by hand after `adb push`.
- One run per device: `run-flows.ps1` and `audio-timing.ps1 -Emulator` take an emulator lease (`tools/lease-common.ps1`, owner `$env:RTST_DEVICE_OWNER`, else `RTST_PHONE_OWNER`) and wait up to 15 min, then exit 4 naming the holder; never run two flows on one serial. `tools/emulator/lint-flows.ps1` runs first in `run-flows.ps1`: every `clearState` needs a `# clearState:` comment above it (it wipes the voice/OCR packs and own books), and only Maestro command names pass. A VM check that needs the network or the voice pack says so in a `# needs:` header; `Invoke-DesktopTest.ps1` prints `VM PREFLIGHT NO-GO` and exits 3 when the guest lacks it. `test-targets.ps1 -Checks` prints the build and test commands the diff needs (Mobile.Shared names both Android apps). A hook sent to the running app uses `launchApp` with `stopApp: false` (Maestro's default restarts the app and can kill it before the hook runs); the lint enforces it, and a flow waits for the hook's visible effect before the next step. The tool self-tests run in CI in `.github/workflows/tools-selftests.yml` (PRs touching `tools/**` or `.maestro/**`). (Slice 207: docs/plan/slices/207-device-test-guards.md; Slice 212: docs/plan/slices/212-flow-hooks-and-tools-ci.md)

- A phone blocked by a corrupt lease file: `lease.ps1 -Show` names it (age, when it frees); `lease.ps1 -Clear -Corrupt` removes only a corrupt file. Both phone build scripts take their `dotnet build` line from `Get-PhoneBuildArguments` in `tools/phone/common.ps1`; never copy it. (Slice 216: docs/plan/slices/216-phone-tooling-leftovers.md)

- run-checks has one budget clock (`Get-BudgetStart` / `New-BudgetClock`); lease wait, quiet wait and elapsed time all read it, so never add a second start time. (Slice 216: docs/plan/slices/216-phone-tooling-leftovers.md)
- Phone checks never cut the network link they are driven over: on a wireless adb serial block only the app (`cmd netpolicy add restrict-background-blacklist <uid>`; it did not cut a running dataSync foreground-service download on the S21, so pack-download checks use the Debug hook `drop-pack-network`), start a detached device-side restore first. `Assert-WholeDeviceNetworkCutAllowed` (`tools/phone/common.ps1`) refuses a whole-device cut on a wireless serial, but no check calls it yet (Slice 225 item 14): call it before any whole-device change. The ClaudeSkills `phone-network-guard` hook refuses typed cuts. (Slice 208: docs/plan/slices/208-paused-pack-downloads-tell-you-and-finish.md)
- `cmd netpolicy restrict-background-blacklist` did not cut the app while it ran a dataSync foreground service (likely the foreground-service exemption; not proven); use a Debug hook (`drop-pack-network`) instead. (Slice 233: docs/plan/slices/233-paused-notice-same-on-android-and-ios.md)
- `pm clear` (`reset-dev-app -Level clear`) revokes POST_NOTIFICATIONS; re-grant it before a notification check. (Slice 233: docs/plan/slices/233-paused-notice-same-on-android-and-ios.md)
- `run-checks` needs `RTST_PHONE_OWNER` exported, or it waits on its own lease. (Slice 233: docs/plan/slices/233-paused-notice-same-on-android-and-ios.md)
