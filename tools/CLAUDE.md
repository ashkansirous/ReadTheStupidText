# CLAUDE.md — tools

Rules for the device-test tooling (`tools/emulator`, `tools/phone`, `tools/desktop-vm`; the VM scripts have their own file).

- Start device checks from `run-flows.ps1 -App auto` / `Invoke-DesktopTest.ps1 -App auto` (they test only the apps the diff touches); never drop an app it names.
- Builds are cached by input hash in `<worktrees>/_builds` and run outside the device locks; the enforced limit is one emulator running flows plus the VM (`RTST_ALLOW_TWO_EMULATORS=1` allows two emulators, never with the VM).
- Phone runs need the phone charging; for network it must be unlocked once with the `.dbg` app in the foreground.
- Unattended phone runs (nobody to unlock) need the screen lock set to None or Swipe: starting a pack download, opening a book or a Settings page needs the app visible. Ask the user before they leave. Run `tools/phone/preflight.ps1` first (NO-GO means stop and ask); take the phone with `lease.ps1 -Take -Owner <name>` and set `RTST_PHONE_OWNER` (one harness script per device at a time). Switch language, voice and Translate through the app's Settings with `tap.ps1` (no hook exists yet); never report them "no hook". On a broken dev app run `reset-dev-app.ps1 -Level auto` (it moves the packs aside and back, never deletes them), record the bug and go on, never stop the run. (2026-10-29 S21 night: docs/plan/notes/2026-10-29-s21-night-runs.md)
- Maestro is not on the PATH: it lives in `<worktrees>/.tools/maestro` (or `$env:MAESTRO_HOME`) and `run-flows.ps1` finds it there. Run flows through that script; never report "Maestro not installed" without checking that folder. (2026-10-30: Slice 201's flow was left unrun on that wrong claim.)
- Maestro flows that need a pushed file live under `.maestro/<app>/needs-file/`, so `run-flows.ps1` skips them; run them by hand after `adb push`.
- One run per device: `run-flows.ps1` and `audio-timing.ps1 -Emulator` take an emulator lease (`tools/lease-common.ps1`, owner `$env:RTST_DEVICE_OWNER`, else `RTST_PHONE_OWNER`) and wait up to 15 min, then exit 4 naming the holder; never run two flows on one serial. `tools/emulator/lint-flows.ps1` runs first in `run-flows.ps1`: every `clearState` needs a `# clearState:` comment above it (it wipes the voice/OCR packs and own books), and only Maestro command names pass. A VM check that needs the network or the voice pack says so in a `# needs:` header; `Invoke-DesktopTest.ps1` prints `VM PREFLIGHT NO-GO` and exits 3 when the guest lacks it. `test-targets.ps1 -Checks` prints the build and test commands the diff needs (Mobile.Shared names both Android apps). A hook sent to the running app uses `launchApp` with `stopApp: false` (Maestro's default restarts the app and can kill it before the hook runs); the lint enforces it, and a flow waits for the hook's visible effect before the next step. The tool self-tests run in CI in `.github/workflows/tools-selftests.yml` (PRs touching `tools/**` or `.maestro/**`).
