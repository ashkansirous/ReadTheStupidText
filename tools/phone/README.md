# Real-phone audio and timing checks (Slice 165)

Audio quality and speed are checked on the user's own phone, over **wireless adb only (never USB)**, not on the emulator
(it cannot say how the voice sounds, and it runs the neural voice on a PC CPU).

- `connect.ps1` looks at `adb mdns services` / `adb devices`. A ready wireless phone is printed and exits 0. Otherwise it prints the
  exact ask (pairing IP:port and the 6-digit code from *Developer options > Wireless debugging > Pair device with pairing code*, then
  the connect IP:port) and exits 2. Pass those as `-PairAddress -PairCode -ConnectAddress` to pair and connect. `-Serial` checks one serial.
- `audio-timing.ps1 -App rtst|dino [-Rates 1,2 (comma list, 0.5-2.0)] [-GapLimitMs n] [-VoiceChanged] [-SkipInstall]` builds the arm64 Debug build, installs it as
  **`<app id>.dbg`** (a second package, so the Play install, its data and its signature are never touched; nothing is uninstalled; only `-FreshInstall` clears, and it wipes the dev app's own data and re-downloads the voice pack on every run),
  skips first run with the Slice 162 hook, then reads the same fixed passage (both apps) through the `read text=... speed=...` hook at each rate
  (the speed goes to the reader; nothing is stored), and prints per read: time to first audio (from the app's own `HOOK read start` line), per chunk
  audio / play / audio-ready time and the gap beyond the audio length (flagged over `-GapLimitMs`), and the total against the audio length at that rate.
  The first run downloads the voice pack: progress lines show, and `-PackTimeoutSeconds` (default 1200) bounds it.
  `-VoiceChanged` adds one `listen now: ...` line; the script never asks anyone to time anything by hand.
  `-LogFile <saved logcat>` re-prints a table from a saved log of one read (pass `-Rates 2` for a 2x log; raw logs of each run are in `<worktrees folder>/.phone/` and hold every log line of the dev app's own process (`--pid`, all tags, so other app log text can appear), never other apps' lines).
- The phone may stay locked only while it is charging (`svc power stayon true` works only then) or with the keep-awake loop: on battery the script prints a "plug the phone in" warning and wakes the screen with `KEYCODE_WAKEUP` every 15 s for the whole run (no unlock, no taps), stopped at the end. Nothing is tapped. It never unlocks, changes settings or touches the volume.
- Markers: the Slice 162 `READ_START`, `CHUNK n`, `READ_END` (tag `RTST-TEST`) plus `CHUNK_AUDIO n <ms>` (Debug builds only: `ReadTimingTracker` raises a static event, `TestMarkers` writes it through `TestHookLog`, same tag).
  Debug builds send no analytics (`UsageGate`).
- Gap = time between a chunk starting and the next chunk starting, minus the chunk's audio length divided by the rate (a systematic offset exists, so judge it against the baseline in the slice file). Audio-ready time of chunk n = its `CHUNK_AUDIO` minus the previous one's (the first from the read command); synthesis overlaps playback, so it is not pure synthesis time.
- Slice 175: `ENGINE_READY <ms>` (read request to engine built and loaded; for Dino the request is noted before the reading session recasts clashing voices, voices the text and translates it, so those are included and not marked separately; -1 when no hook asked for the read) and `CHUNK_SYNTH n start|end <ms>` (ms since the engine was ready; `start` only for chunk 0, because later chunks are generated in parallel and only their end is observable from `ReadTimingTracker`). The table adds an `engine ms` and a `synth end ms` column and a line splitting a cold start into engine load and first-chunk synthesis (chunk 0's `synth end` is the cold synthesis time).
- iOS: no Mac or iPhone here; iOS audio checks stay with TestFlight internal testers.
- Reading starts through the Debug `read text=... speed=...` hook, so no unlock or tap is needed (the phone must be charging or the keep-awake loop running). Dino reads a real starter book page (Slice 175): `audio-timing.ps1 -App dino [-Book three-little-pigs] [-Page 1]` sends the Debug `open-book id=... page=n play=page speed=...` hook, which opens the reading screen on that page (the package id, story id or title slug is accepted) and reads that page on the reading session, the same path as the Play button, in each character's voice (`play=page` stops after the page, `play=1` reads on to the end of the book, no `play` only opens the page). The gap limit default (1300 ms) comes from the re-run baseline in the slice file: the gap beyond the audio length is a systematic 350-400 ms at 1x and 750-900 ms at 2x, so the limit is the worst of those plus about 50%; a regression at 1x smaller than about 0.9 s will not be flagged, so compare the numbers with the baseline too.
- Slice 177 options: `-Emulator [-Serial emulator-5556]` (headless emulator, default `emulator-5554`), `-Aot` (AOT-compiled Debug build: the only way to measure Release speed, because the test hooks exist only in Debug builds), `-Warm`, `-FreshInstall`, `-SettleSeconds n`.
- Slice 180, never wait in silence (`audio-timing.ps1`): the power state (`dumpsys battery`, `mWakefulness`) is printed first; the app must log within `-FirstLogSeconds` (60) of launch (read by pid, not by tag alone); the pack download fails as `pack download stalled at N bytes` when its `.partial` file does not grow for `-PackStallSeconds` (120), progress printed every 30 s; a read with no new app log line for `-ReadSilenceSeconds` (120) fails with the last line seen.
- Slice 180 follow-up, builds use the cache: `audio-timing.ps1` reuses the APK from the shared build cache (`tools/emulator/build-cache.ps1`, key = hash of the build inputs) instead of rebuilding every run. The cache name carries the dev package, ABI and AOT flag (`<app>-android-dbg-arm64[-aot]-<key>`), so the phone's APK and the emulator's x86_64 one never mix. It prints `Reusing cached <app> APK (key ...)` or `Building <app> APK (key ...)`; `-Rebuild` forces a build. The build runs before the quiet-machine lock (BelowNormal priority); only the install and the timing run inside it. `-SkipInstall` under `-Emulator`/`-Aot` still checks the installed APK against the cached one.
- Start it with `pwsh -NoProfile -File tools/phone/audio-timing.ps1 ...` (PowerShell tool or `Start-Process pwsh`). A launch from Git Bash as `(powershell -File ... &)` used to die with "cannot call a method on a null-valued expression" right after "Waiting for a quiet machine": `Invoke-Adb` used `ProcessStartInfo.ArgumentList`, which Windows PowerShell 5.1 lacks. Fixed in `common.ps1`, so both shells work.
- Settings by hook (Slice 209, Debug builds, Android broadcast and iOS URL alike): `set-language lang=<code>` (RTST: the Settings Language row's path, then the shell is rebuilt; Dino: the Language page's pick path, then the root is rebuilt; Dino starts the voice pack only with `voice=1`, as the real-phone check sends; the default skips it because it crashes the Debug x86_64 emulator build) answers `HOOK set-language ok <code>` (Dino with `voice=1` answers `started` first, then `ok` only once the language is stored, which waits for the previous language's pack download) or `failed unknown <code>`; `set-voice id=<voice id|auto>` (RTST, `system` is the phone voice, `auto` picks the installed pack's first voice that is not in use and answers with its id) answers `HOOK set-voice ok <id>` or `failed unknown <id>`; `stage-book-update id=<book> [force=true]` (Dino; `force=true` stages the store's version even when the phone's copy already matches it, sets the recorded version one lower so the next start really swaps it, and answers `ok <id> v<n> forced`; the check passes it) downloads the store's newer version of the book into `book-updates/` as the 7-day check would, answers `HOOK stage-book-update started`, then `ok <id> v<n>` or `failed <reason>` (offline, not in the store, edited, UpToDate, not on the shelf), and the next cold start applies it with the `[BookUpdate] apply start` / `apply end after <ms> ms` lines. Use these before `tap.ps1`. Runner checks: `language`, `voice`, `book-update` (`run-checks.ps1 -App rtst|dino -Checks language,voice,book-update`). `set-translate mode=on|off` (RTST) sets the Review page's per-text Translate tick for the text on screen (mobile Translate is that tick, not a stored setting, so there is no `from=`); off the Review page it answers `HOOK set-translate failed not-on-review`, and before the row shows (text not yet detected as foreign, or no model) `failed unavailable`; the next read logs `READ translated`. Runner check `translate`.
- The hook broadcast action is `uk.sirous.rtst-test.TEST_HOOK` for RTST and `uk.sirous.dino-test.TEST_HOOK` for Dino (`Get-HookAction` in `common.ps1`). A wrong action fails silently (no error, no log line); when the app logs no `HOOK` line within 30 s, the script names the action it sent.
- Slice 206, unattended runs (all wireless adb, all exit 2 with the pairing ask when no phone is connected; self-tests with no device: `test-phone-lib.ps1`, `test-tap.ps1`, run in `pwsh` and `powershell`):
  - `preflight.ps1 [-Serial s] [-App rtst|dino|both] [-Fix]`: one go/no-go before leaving (connected, charging, screen lock None or Swipe, stay-awake-while-charging: `stay_on_while_plugged_in` must have the bit of the charger in use, 1 AC / 2 USB / 4 wireless, free space on /data over 2 GB, the `.dbg` apps and their versionName, the phone lease: holding none is a warning). Read-only on the phone; `-Fix` is the only thing that writes (sets stay-awake to 7). Last line `PREFLIGHT GO` (exit 0) or `PREFLIGHT NO-GO: <reasons>` (exit 1). A lock state it cannot read is NO-GO, not a guess.
  - `reset-dev-app.ps1 -App rtst|dino [-Level setting|clear|reinstall|auto]`: the reset ladder for a broken dev install. Only the two `.dbg` packages (hard-coded allow-list). `setting` puts the app language back to English in its preferences; `clear` copies the packs to `/sdcard/Download/rtst-packs-aside/<pkg>/packs-<time>.tar` (the newest 3 per package are kept, older ones deleted), `pm clear`, copies them back and relaunches with the skip-first-run hook; if putting the packs back fails, `auto` stops (STOPPED line) and leaves the copy for a hand restore; `reinstall` adds `adb install -r` of the cached APK (build it once with `audio-timing.ps1`); `auto` tries them in that order and prints which one worked.
  - `tap.ps1 (-Text t | -Id resource-id | -Desc content-desc | -List) [-Index n] [-Scroll] [-WaitSeconds 10] [-App rtst|dino] [-Package <dev package>] [-ExpectText t]`: finds the element in a `uiautomator dump` (exact match first, then case-insensitive contains), taps its centre, prints the nodes that changed after (the status bar is ignored). Only the expected app is tapped: `-Package` (default the `.dbg` package of `-App`, default `rtst`; must be one of the two dev packages); exit 6 and no tap when another app (the store app, the launcher) is on screen. A contains match with several hits and no `-Index` exits 3 listing them. Exit 3 also when nothing matches (lists the clickable texts), 5 when `-ExpectText` is missing afterwards, 7 when the tap was sent but no dump after it could be read (the tap is never repeated; look at the screen first). `-Scroll` swipes up to 6 times. Use it to switch language, voice and Translate through Settings.
  - `lease.ps1 -Take -Owner <name> [-Minutes 120] | -Renew -Owner <name> [-Minutes 120] | -Release -Owner <name> | -Show`: one session at a time. Lease file `<worktrees folder>/.phone/lease-<ro.serialno>.json` (keyed by the phone's own serial, taken under a mutex); an expired lease is free; a corrupt lease file is held until it is older than 24 h or removed by hand. After `-Take` set `$env:RTST_PHONE_OWNER` to the owner name: `audio-timing.ps1` (not with `-Emulator`), `reset-dev-app.ps1` and `tap.ps1` exit 4 when a live lease belongs to someone else, and renew the caller's own lease by themselves when under 15 min remain. No lease means allowed (preflight warns).
- Slice 213, one check runner with a fixed time budget (`run-checks.ps1`): device briefs name checks, they do not describe procedures. `pwsh -NoProfile -File tools/phone/run-checks.ps1 -App rtst -Checks cold-start,highlight,notification-text [-Budget 10] [-Runs 3] [-Reinstall]`; `-App dino -Checks book-end`.
  - It takes the same per-phone lease as `lease.ps1` (owner `RTST_DEVICE_OWNER`, else `RTST_PHONE_OWNER`, else `run-checks-<pid>`; exported as `RTST_PHONE_OWNER` for the scripts it starts; released at the end unless the caller already held it), waits for the quiet machine, installs the cached APK with `adb install -r` (data and packs stay; the phone keeps a marker of what run-checks installed) when the phone has none or run-checks itself installed another build or variant (at most one swap per run, Debug to AOT; packs are checked again after it). An app run-checks did not install is never replaced silently: every check is SKIPPED unless `-Reinstall`. The budget clock starts when the runner starts; the lease and quiet-machine waits are capped at 3 minutes each (then every check is SKIPPED `waited too long for <holder>`). A lease the caller holds is only extended, never shortened. Every failure path still prints the table (exit 7 when the runner itself broke). `cold-start` reports MEASURED, never PASS, runs `preflight.ps1` (only connection, charging and a secure lock screen stop it; other FAILs print as warnings), then setup on the dev install (`POST_NOTIFICATIONS` granted, no-usage marker, voice packs restored from `reset-dev-app.ps1`'s aside copy when moved), then each check in turn. Preflight runs with `-Fix` (stay-awake is the only phone setting the runner changes) and prints one line, `preflight: GO` (with its warnings) or `preflight: STOP - <reasons>`; only not connected, no charger, a secure or unreadable lock screen and no free space (under 0.5 GB) stop the run. A timed run never downloads a voice pack. An installed pack is `files/packs/<id>/active` (marker naming the version folder) plus `files/packs/<id>/v<n>/pack.json`; `Test-PackInstalled` (common.ps1) is the one check, and a `files/packs/<id>-<version>.zip.partial` is never a pack. Pack installed -> go; not installed but an aside copy exists (`reset-dev-app.ps1` or `-Prepare` wrote it) -> restored and verified with the same check; else the checks that need a pack are SKIPPED `no pack: run -Prepare first`. `run-checks.ps1 -Prepare -App <app>` runs outside any budget (like `-Build`): it deletes the stale `.partial` of the needed pack, launches the dev app in the foreground, requires a `PACKDL start` line within 60 s (else FAIL quoting the app's last 10 `RTST-TEST` lines), waits for the pack to pass the install check (progress every 30 s; a `.partial` not growing for 2 min is a FAIL), then saves a verified aside copy of the installed pack folders only (never a `.partial`; newest 3 kept). `-Reinstall` installs the cached build again even over the same one and prints adb's exit code and the `lastUpdateTime` change; an install that did not happen fails the stage with adb's output. `notification-text` checks that the required pack is still installed afterwards (else FAIL).
  - **Builds start with the run, in the background.** The Debug and the AOT build both start at once (skipped when cached; same cache and names as `audio-timing.ps1`, so the two share builds; truly in parallel in one checkout: each build has its own `dotnet build --artifacts-path <worktree>\.artifacts\<app>-<jit|aot>`, restore included, so nothing under `src\*\obj` or `src\*\bin` is touched; the build lock is per checkout and variant). Each check declares the build it needs: `cold-start` (any timing) needs `aot` and waits for it (what it waits for is printed every 30 s); the others start on whichever is ready first, AOT preferred. One swap at most, Debug to AOT, never back. A failed build, or one whose log did not grow for 5 minutes, FAILs the checks that need it with its last 20 log lines; nothing is skipped for a missing build or falls back silently. The 10-minute budget runs from the runner start; time spent only waiting for a build is added to the end of it, so a cold build never eats the checks (lease and quiet-machine waits are capped at 3 minutes each and do count). Status for the coordinator's 10-minute check: `<worktrees>\.phone\build-<app>-<debug|aot>.json` (state, start, heartbeat, last log line, log path) and `<worktrees>\.phone\run-status.json` (each build, each check, the installed variant, updatedUtc; rewritten at least every 30 s). Every table row and timing is labelled `[aot]` or `[debug]`. `-Build`/`-Prepare` take `-Variant debug|aot` (default `debug`); `-Prepare` builds first when the APK is not cached.
  - The budget (`-Budget`, default 10 min, counted from the runner start) covers the whole device stage except time spent only waiting for a build, which is added to the end. A check starts only when its estimate fits what is left, and is stopped as `TIMEOUT` when the time is gone; the table at the end names every skipped check and why. Exit: 0 all passed, 1 failed or timed out, 2 no phone, 3 some skipped, 4 phone leased by someone else, 5 preflight NO-GO, 6 build failed.
  - Checks, one script each in `checks/` (add a check as a file there plus a line in the catalogue in `checks/_lib.ps1`): `cold-start` (per run: force-stop, empty `<app data>/cache/sentences`, relaunch, read; prints first audio, engine-ready and first synthesis, then the median; repeat runs on a warm sentence cache read 240-578 ms), `highlight` (RTST: types three sentences in the reader and taps Read through `tap.ps1`; passes on a `SENTENCE <chunk> <n>` marker with n >= 1 before `READ_END`; needs the neural pack), `notification-text` (RTST: throttled download of a pack language that is not installed, reads `dumpsys notification --noredact`, title must be a status with a percentage; skips as a failure when every candidate pack is installed), `short-lines` (Dino, Slice 220: reads the Slice 210 short lines on chosen Kokoro voices and prints, per read, what Kokoro returned on the normal engine and on a single-thread engine (3 takes each: samples, NaN count, peak, voiced ms) from the guard's two Debug `short line probe` lines, with a summary per arm and per outcome; passes when every read ended, has a probe line and none gave up; one voice by default, `-AllVoices` for the four failing ones), `book-end` (Dino: `open-book ... play=1 speed=2` to `READ_END`, then time until the app holds no wake lock or foreground service), `paused-notification` (RTST, Android 15 only: lowers the dataSync timeout to 30 s, backgrounds the app mid-download, asserts the "Download paused. Tap to finish." notification with the language and size and its marker `PACKDL service paused-notified`, fires the notice's content intent and asserts the app is back in front; resets the timeout and restores the pack in a finally block; Slice 208).
  - Self-test with no device: `test-run-checks.ps1` in `pwsh` and `powershell`.
- Slice 216, leftovers from the Slice 213 runs (self-test with no device: `test-phone-leftovers.ps1`, in `pwsh` and `powershell`):
  - `audio-timing.ps1` empties the dev app's sentence cache (`cache/sentences`, app stopped first) before every read it reports as cold and labels the table `COLD (sentence cache emptied)`; `-Warm` reads stay labelled `WARM`. Its raw logs go to `<worktrees folder>/.phone/` like the runner's.
  - One build command: `Get-PhoneBuildArguments` in `common.ps1`, called by `audio-timing.ps1` and `run-checks.ps1` (the self-test fails if either grows its own copy). Both first call `Assert-BuildPathLength`, which warns when the artifacts folder plus the deepest MAUI intermediate (an unmeasured estimate, `$script:DeepestMauiIntermediateChars`) would pass 260 characters, and fails with `path too long: ...` only when the folder plus a 100-character floor already passes 260.
  - Lease length (`run-checks.ps1`): a timed run writes budget + 15 min (25 at the default budget), `-Prepare` writes 45 + 15 = 60, and a longer own lease is kept, never shortened; the run prints `phone lease: N min (why)`. That is why preflight showed different expiry times in different modes.
  - `lease.ps1 -Show` (and every script that names a lease holder) says `a corrupt lease file (written 3 h 10 min ago, frees itself at HH:mm; lease.ps1 -Clear -Corrupt removes it now)`; `lease.ps1 -Clear -Corrupt` removes the file only when it does not parse (a valid lease, live or expired, is never touched).
  - `repro-pack-survives-install.ps1 -App rtst|dino` (written, not yet run): installs the AOT build, then the Debug build over it with `adb install -r`, lists the packs after each and prints `PACKS SURVIVED` or `PACKS LOST`. Survived means the earlier re-download came from `audio-timing.ps1 -FreshInstall`; lost means an app bug (see the slice file).
  - `tap.ps1` prints a screen change as the changed texts only, cut to 120 characters; the full signatures are appended to `<worktrees folder>/.phone/tap-changes.log`. `reset-dev-app.ps1` restores the newest leftover aside archive after a clear/reinstall level's `pm clear`, when the app had no installed pack to keep aside (verified; on failure it says why and the archive stays).
