# CLAUDE.md — worker (landing site, downloads, usage counts, story store)

Rules for the Cloudflare Worker `readthestupidtext` and the sites it serves. Moved word for word from the root `CLAUDE.md` (2026-10-30).

**Landing site.** `readthestupidtext.sirous.uk` is the Cloudflare Worker `readthestupidtext`
(`wrangler.jsonc`, `worker/index.ts`) serving `site/` (not `docs/`); GitHub Pages is off. Deploy with
`npm run deploy` (refuses CRLF site files; `npm run typecheck` keeps `wrangler.jsonc` and
`wrangler.workers-dev.jsonc` in sync) manually when needed. Fast check for any `worker/` change: `npm ci && npm run typecheck` (a fresh worktree has no `node_modules`, and without them `tsc` never runs; Slice 219 went red in CI that way). Workers Builds deploys `main` only (preview-branch builds are off); deploy
command `npm run deploy`, watch paths `worker/*`, `site/*`, `wrangler*.jsonc`, `package*.json`. A Worker custom domain can't replace an existing DNS
record: delete it first (wrangler has no DNS scope). Privacy policy edits touch both `PRIVACY.md` and
`site/privacy.html`. Don't add `docs/CNAME` or a GitHub Actions deploy. See `docs/DEPLOYING.md`.
The Worker also serves `dinoreader.sirous.uk` -> `site/dino/` (workers.dev: `/dino/` prefix); host routing is in `worker/downloads.ts` (`resolveSite`), every `run_worker_first` path needs its `/dino` twin (`check-configs` enforces), and the Dino site makes no third-party requests (kids' app).
Usage counts (`POST /api/events`, `worker/events.ts`, Slice 133) write to Analytics Engine through the `DINO_USAGE` binding (dataset `dino_usage`), declared in both `wrangler.jsonc` and `wrangler.workers-dev.jsonc` (Analytics Engine is enabled on the account; a deploy fails without it). Counting is switched by `telemetry.enabled` (and `sampleRate`) in `dinoreader/config.json`; never set it to true for an app before its store privacy rows in `plan.md` are ticked (Decision 145).
Usage events carry only closed-list fields, no id except Dino's per-launch session id (below), no typed text and no own-book title; `source` is `shelf`+id only for starter/store books, else `own`. Count with `SUM(double1)`, not `COUNT(*)`, because of sampling. (Slice 133: docs/plan/slices/133-dino-anonymous-usage-counts.md)
Test builds and devices never send: debug builds, unstamped versions (`1.0`/`1.0.0`/`0.0.0`...), emulators/simulators and Firebase Test Lab, decided by `UsageEligibility` (Application/Usage) and `UsageGate` (Mobile.Shared/Usage); the Worker also drops unstamped versions (`worker/events.ts`). (Slice 167: docs/plan/slices/167-no-test-device-counts.md)
**Session id and playback events (Slice 250).** Dino counts carry an optional `session` (32 lower-case hex digits, random, made at each cold start, kept in memory and on disk only inside unsent queued counts, never reused for a later launch or tied to an install, device or person) and `seq` (order inside the session, from 1). `dino_usage` columns: `blob16` = session (empty when none), `double2` = seq (-1 when none); `blob9` = detail, `double1` = sampling weight (still `SUM(double1)`). A malformed `session` or `seq` is dropped from the row, never the event; a `seq` without a valid session is dropped too. Sampling is decided once per session by the app, so a session is complete or absent. New names `read_started`, `read_paused`, `read_resumed`, `book_left` (no detail) and `read_stopped` (detail one of `left_book`, `finished`, `cancelled`, `language_changed`, `restarted`, `window_stopped`, `skipped`, `failed`, `other`; `window_stopped` is accepted but not emitted yet). Analytics Engine allows 20 blobs and 20 doubles per point, so 16 and 2 are used. **One session in order** (the `analytics-query` agent's column map gains `session` and `seq`; name the dataset, `dino_usage` for production): `SELECT double2 AS seq, blob1 AS name, blob2 AS book, blob9 AS detail, timestamp FROM dino_usage WHERE blob16 = '<32 hex>' ORDER BY double2`. Timestamp is the batch's send time, so order by `seq`, never by timestamp. Slice 248's bug reads as `book_left`, then no `read_stopped`, then `read_resumed`/`read_paused` while another book is open. A crash or user report holds the same id (`session` in the stored JSON; `pull-crashes.mjs` prints it), so a reported code leads to that session's rows. (Slice 250: docs/plan/slices/250-dino-playback-events-and-session-id.md)
**Beta dataset (Slice 251).** A Dino iOS TestFlight or App Review build (`UsageEligibility.ChannelOf`, `UsageGate.Channel`; only Dino sets `SendsBeta`, RTST and crash reports keep the old yes/no) posts its counts to its own route `POST /api/events/beta` (`BETA_EVENTS_PATH`, also `/dino/api/events/beta`, in `run_worker_first` of both wrangler configs), which `worker/events.ts` writes only to `DINO_USAGE_BETA` (dataset `dino_usage_beta`, declared in both configs; it needs no `DINO_USAGE`, without it a 503). The production route `/api/events` writes only `DINO_USAGE` and answers 400 to a body with `channel: "beta"`. An older or rolled-back Worker has no beta route and answers 404, which the app drops, so beta rows can never land in `dino_usage` (no field to ignore). RTST answers the beta path 404. `dino_usage_beta` holds App Review traffic as well as testers'. Never mix the two in a report: the `analytics-query` agent names the dataset it reads, and production questions read `dino_usage` only. Android: no way to tell a Play testing track from production on the device (see the slice file). (Slice 251: docs/plan/slices/251-dino-beta-usage-dataset.md)
Robot and own-machine exclusion lives in `UsageEligibility.IsEmulatorBuild`, `UsageGate` and the `worker/events.ts` arch drop (Android/iOS `x64`/`x86`); every test harness must set the off switch (env `READTHESTUPIDTEXT_NO_USAGE=1`, or the Android `no-usage` marker file). (Slice 179: docs/plan/slices/179-no-robot-or-own-machine-counts.md)
Query counts through the Analytics Engine API with the read-only token `CF_ANALYTICS_READ_TOKEN` in `D:\secrets` (`analytics-query` agent); Dino `blob10-15` / RTST `blob18-20` + `double2-3` hold country and device buckets. (Slice 166: docs/plan/slices/166-usage-device-context.md)
The `fallback` count (Slice 273, both apps): a feature fell back to something else. Dino: `detail` is `<area>:<reason>` from `FALLBACK_AREAS` x `FALLBACK_REASONS` (`worker/events.ts`; the apps' `FallbackArea`/`FallbackReason` in `Application/Usage/FallbackKind.cs` must be the same lists, a test in each suite compares them), about a book or no book, and the optional whole numbers `count` (times this session; for `read_voice` the pieces read by clips) and `deviceCount` (pieces read by the device voice) are `double3`/`double4` (-1 for none; a malformed one is dropped from the row, not the event). `read_voice` is `premade` only when every spoken piece had a clip, `partial` when some fell back; a read of a book with no pack published (an own book, or no pack in that language, `device:no_pack`) is a `read_voice` but never a `fallback`. **Once per session with a count:** the first occurrence of each (area, reason, book, language) in a session is sent at once with `count` 1; if it happened again, one more row with the session total is sent at each usage flush (book left, app stop or sleep, start-up) when the count grew since the last row, so a session can have several rows, never one at session end only; `FallbackTally`, shared by both apps. **Queries take `MAX(double3)` per session (`blob16`) + area + reason, and always filter on `blob1` (the event name)**, because `double3`/`double4` mean different things per event: `fallback`: `double3` = times this session, `double4` = none (-1); `read_voice`: `double3` = pieces read by clips, `double4` = pieces read by the device voice; other events: -1. The fallback reason of a `partial` read is `text_mismatch` or `clip_missing`, whichever caused more of its misses (a tie says `text_mismatch`). RTST has all 20 blobs in use, so its `fallbackArea` and `fallbackReason` are stored in the `stage` and `outcome` blobs (a fallback carries neither; every RTST query filters on the event name, and a test keeps the area and reason lists from ever equalling a stage or outcome) and `count` is `double4` there (RTST's `double3` is not the count), so name the dataset in every query. New areas and reasons are appended to the two lists inside the part that adds them; never free text, a file name or book text. Part B adds the areas `speech` and `translation` (shared code reports through `IFallbackSink` in `Application/Usage`; RTST answers with `FallbackReporter`, Dino with `DinoFallbackSink` as a count about no book). Part C adds the areas `pack`, `ocr`, `document`, `store`, `config` and `ui_language` (reasons in the `FallbackKind.cs` block "Part C"). Part D adds the areas `window`, `font` and `library` and reasons for the swallowed-catch class (block "Part D"); a catch that is not a fallback carries `// no-fallback: <reason>` on the line after its opening brace (Slice 273 part D). **A config fallback is reported through a sink that only queues a count, never from the usage sender's send path and never by fetching the config**, so it cannot loop; with no config held (telemetry still off by default) a `config_default` count is dropped by the same gate as every other count.
The Dino host also serves the free story store (Slice 92): `GET /api/stories`, `/api/stories/<id>/cover` and `/api/stories/<id>/download[?v=n]` (`worker/stories.ts`, Dino only; `/api/stories` and `/api/stories/*` plus their `/dino` twins are in `run_worker_first`). Every Dino book (starter or store) is a folder `content/dino/<stem>/` (`story.md`, `book.json` with the id, version, ages, author, credits, colour, voices and content hash, `pictures/`, `cover.jpg`, `cover-thumb.jpg`, `translations/`, `art.md`); `dotnet run --project tools/DinoReader.BookBuilder -- build` writes `artifacts/store/<id>/` and the committed starters, `check` fails when a STARTER changed without `stamp` (which raises its version; a store book needs none, Slice 239: `publish-store` versions it from its content hash and delists a story whose folder is gone) and runs in CI (Slice 157, Decision 162: docs/plan/slices/157-dino-book-content-out-of-tests.md). Store stories are built with `build` (to `artifacts/store/<id>/`) and uploaded **automatically on every merge** by `release.yml`'s `publish-store` job (the `dinostore` target; every book whose content hash differs from the live one, as live + 1; Slice 158, 239, Decision 163); `tools/upload-store-story.ps1 <id>` is the manual fallback. Either way the files go to `dinoreader/stories/<id>/{meta.json, cover.jpg, story-v<n>.dino}` in the downloads bucket, `meta.json` last: a folder is listed only with `meta.json` and a package, and `meta.json` carries `schemaVersion` (the `.dino` format), `title`, `language`, `pageCount`, `minutes`, optional `version`/`added`/`credits`/`creditsByLanguage` (language code to credit line, all 14 non-English languages per book, capped like `credits`; the card shows the app language's else `credits`; `check` enforces it; not in `BookHash`, so editing never bumps a version; Slice 192: docs/plan/slices/192-dino-store-credits-in-every-language.md), `ageMin`/`ageMax` (both or neither; integers 0-18, min <= max, else both dropped) and `author` (trimmed, max 100; Slice 112) (`worker/stories.ts` trims `credits` and caps it at 200 characters; Slice 102). The story id is the package id; upload a new `story-v<n+1>.dino` rather than overwriting a version (`?v=` is cached for a day).
A store book may also have an **audio pack per language** (Slice 246 B2): `audio-<lang>-v<n>.zip` in the same folder, listed in `meta.json` as `"audio": {"<lang>": {"version": n, "bytes": b}}` (written by `BookBuilder build-audio`, which keeps the version in the book's `audio-cast.json`; the list item gets `audio` with a `url`). `GET /api/stories/<id>/audio/<lang>?v=<n>` serves the zip (immutable, cached a day) only when meta lists that language at that exact version AND the zip is in the folder; a missing, wrong or unlisted `?v=`/language is a 404, and a listed pack nobody uploaded is simply not offered. Upload packs before `meta.json` (`tools/upload-store-story.ps1` does); never overwrite a version. Old app builds never ask. Tests: `worker/stories-audio.test.mjs`.
Each pack may also have a **listening track for smart speakers** (Slice 281): `listen-<lang>-v<n>.m4a` (AAC, the pack's clips joined in read order, built by `BookBuilder build-listen`), listed as `listenSeconds` in the pack's `meta.json` `audio.<lang>` entry; the list item then carries `listenUrl` (`/api/stories/<id>/listen/<lang>?v=<n>`) and `listenSeconds`. The route serves `audio/mp4` inline with Range, HEAD and conditional support (the same `serveObject` as the zip) and answers 404 unless meta lists that language at that exact version with `listenSeconds` AND the .m4a is in the folder (a listed length without the file is dropped from the offer). No auth, and no usage count for plays (closed event list). Tests: `worker/stories-listen.test.mjs`. (Slice 281: docs/plan/slices/281-dino-listening-tracks.md)
The Dino host also answers an anonymous **Sonos music service** (Slice 283): `POST /sonos` (and `/dino/sonos`, both in `run_worker_first`; `worker/sonos.ts` + `sonos-soap.ts`, SOAP by hand, any other method 405). Its catalogue is the `/api/stories` list read through `handleStories` (only a book with `listenUrl` in a language appears, under that language; the root lists languages in their own names, a language lists its books as one playable `audio/mp4` track each, ids `lang:<code>` and `track:<code>:<storyId>`); `getLastUpdate`'s `catalog` is a hash of the offered tracks. Every failure is a SOAP fault with HTTP 500 (`Client.ItemNotFound` for an unknown id). No household or account state, the credentials header is ignored, and nothing is logged (no ids, titles or faults). Tests: `worker/sonos.test.mjs`. (Slice 283: docs/plan/slices/283-dino-sonos-music-service.md)
The Dino host also serves the remote config (Slice 132): `GET /api/app-config` (`worker/appconfig.ts`, Dino only, `/api/app-config` and its `/dino` twin in `run_worker_first`, read from R2 on every request so a changed file takes effect at once) from the R2 object `dinoreader/config.json` in the downloads bucket: `{"android":{"minVersion":"1.2.0","latestVersion":"1.3.0"},"ios":{...},"windows":{...},"telemetry":{"enabled":false,"sampleRate":0}}`. Change it with `wrangler r2 object put readthestupidtext-downloads/dinoreader/config.json --file config.json --remote`; a missing or bad file (or field) means no forced update and telemetry off. To force an update set that platform's `minVersion` above the oldest build you still allow.
The RTST host also serves `/api/events` and `/api/app-config` from `readthestupidtext/config.json` (Slice 137); its `RTST_USAGE` binding (dataset `rtst_usage`) is in both wrangler configs, switched by `readthestupidtext/config.json` the same way. (Slice 137: docs/plan/slices/137-rtst-phone-usage-counts.md)

- Crash and error reports from the phone apps (`POST /api/crash`, `worker/crashes.ts`, both hosts and their `/dino` twin; Slice 227): each valid report is kept whole in R2 at `crashes/<app>/<yyyy-mm-dd>/<random id>.json` (the Worker names it; no sender id, IP never stored, `CRASH_LIMITER` rate limit keyed by IP only inside Cloudflare; the binding is required: without it the endpoint answers 503 and writes nothing; nothing under `crashes/` is ever served: `serveObject` refuses it) and counted once in the Analytics Engine dataset `app_crashes` (`APP_CRASHES`), both declared in both wrangler configs. Switched by `crashReports.enabled` in each config object (`dinoreader/config.json`, `readthestupidtext/config.json`; default off, missing = off, read through the same 60 s cache as `telemetry`): never set it to true before the Play Data safety "Crash logs" and App Store "Crash Data" forms are saved (`STORE.md`, Slice 227 item 8). The user's exception to the production-only rule (2026-10-31): **TestFlight installs send crash reports**, tagged `testflight`, and stay out of the usage counts; debug builds, unstamped versions, emulators, Firebase Test Lab, robots (the Worker drops Android/iOS `x64`/`x86` too) and the harness off switch still send nothing (`CrashEligibility` beside `UsageEligibility`). Validation helpers are shared with `events.ts`, not copied. Retention: the Worker never deletes, so an R2 lifecycle rule on the `crashes/` prefix (delete after 90 days, `wrangler r2 bucket lifecycle add readthestupidtext-downloads crash-reports-90d crashes/ --expire-days 90`) is set on the bucket (added 2026-10-31; keep it if the bucket's rules are ever changed; the privacy text says reports are kept only as long as needed); the abuse limits are the per-connection `CRASH_LIMITER` and the 64 KB body cap, with no global cap. `testflight` is accepted only for platform `ios`, and nothing authenticates the sender, so treat the stored reports as untrusted data. A crash report holds no user text: log calls must never carry typed or read text, book titles or file names (the rolling log's tail goes out with the report).
- "Did it crash?" goes to `tools/crashes/`, never a dashboard: `pull-crashes.mjs` (R2 through the Cloudflare REST API with the token of wrangler's own login, `npx --no-install wrangler auth token --json`: no secret to create; the script only calls R2 list + get, but the login is the user's general one, not a read-only or scoped credential, and a 401/403 means wrangler is logged in to another Cloudflare account; Slice 243), `pull-apple.py` (App Store Connect diagnostic signatures and TestFlight crash submissions, key from `D:\secrets\lets-call-mom`) and `pull-play.py` (Play Developer Reporting API, needs the `playdeveloperreporting` scope and the service account added in Play Console). (Slice 227: docs/plan/slices/227-crash-reports.md)
- A `user_report` (Dino "Report a problem") is answered 2xx only after its R2 put; every other path (reports off, dropped version or device, bad code, rate limit) is non-2xx, so the app never shows "Sent" for a report nobody stored. (Slice 249: docs/plan/slices/249-dino-report-a-problem.md)
- Usage versions with major 0 are dropped as unstamped, on the worker (`worker/events.ts` `isUnstampedVersion`) and on the client (`UsageEligibility.cs`); keep the two rules equal. (Slice 219: docs/plan/slices/219-usage-drops-dev-versions.md)
- Dino audio counts (Slice 267): `read_voice` (a shelf or own book; detail `premade` or `device:no_pack|pack_failed|text_mismatch|clip_missing`) and `audio_pack_download` (a shelf book; detail `started|done|cancelled|failed:network|size|unzip|clip|missing|storage`; `cancelled` is a download the reader ended, Slice 275). The lists are `READ_VOICES` and `AUDIO_PACK_OUTCOMES` in `events.ts`; a Core test (`AudioPackUsageTests`) keeps them equal to `AudioPackUsage`. Queries: `docs/analytics/dino-voice-queries.md`.
