# CLAUDE.md — worker (landing site, downloads, usage counts, story store)

Rules for the Cloudflare Worker `readthestupidtext` and the sites it serves.
**Landing site.** `readthestupidtext.sirous.uk` is the Cloudflare Worker `readthestupidtext`
(`wrangler.jsonc`, `worker/index.ts`) serving `site/` (not `docs/`); GitHub Pages is off. **Production deploys only through Workers Builds on a
merge to `main`; never run `npm run deploy` or `wrangler deploy` from a shell** (user, 2026-11-13; `deploy-guard.mjs`
denies it). `npm run deploy` is the pipeline's own deploy command (it refuses CRLF site files; `npm run typecheck` keeps
`wrangler.jsonc` and `wrangler.workers-dev.jsonc` in sync). Batched skip-CI merges skip Workers Builds (Slice 354 item 18). Fast check for any `worker/` change: `npm ci && npm run typecheck` (a fresh worktree has no `node_modules`, and without them `tsc` never runs; Slice 219 went red in CI that way). Workers Builds deploys `main` only (preview-branch builds are off); deploy
command `npm run deploy`, watch paths `worker/*`, `site/*`, `wrangler*.jsonc`, `package*.json`. A Worker custom domain can't replace an existing DNS
record: delete it first (wrangler has no DNS scope). Privacy policy edits touch both `PRIVACY.md` and
`site/privacy.html`. Don't add `docs/CNAME` or a GitHub Actions deploy. See `docs/DEPLOYING.md`.
The Worker also serves `dinoreader.sirous.uk` -> `site/dino/` (workers.dev: `/dino/` prefix); host routing is in `worker/downloads.ts` (`resolveSite`), every `run_worker_first` path needs its `/dino` twin (`check-configs` enforces), and the Dino site makes no third-party requests (kids' app).
Usage counts (`POST /api/events`, `worker/events.ts`, Slice 133) write to Analytics Engine through the `DINO_USAGE` binding (dataset `dino_usage`), declared in both `wrangler.jsonc` and `wrangler.workers-dev.jsonc` (Analytics Engine is enabled on the account; a deploy fails without it). Counting is switched by `telemetry.enabled` (and `sampleRate`) in `dinoreader/config.json`; never set it to true for an app before its store privacy rows in `plan.md` are ticked (Decision 145).
Usage events carry only closed-list fields, no id except Dino's per-launch session id (below), no typed text and no own-book title; `source` is `shelf`+id only for starter/store books, else `own`. Count with `SUM(double1)`, not `COUNT(*)`, because of sampling. (Slice 133: docs/plan/slices/133-dino-anonymous-usage-counts.md)
Test builds and devices never send: debug builds, unstamped versions (`1.0`/`1.0.0`/`0.0.0`...), emulators/simulators and Firebase Test Lab, decided by `UsageEligibility` (Application/Usage) and `UsageGate` (Mobile.Shared/Usage); the Worker also drops unstamped versions (`worker/events.ts`). (Slice 167: docs/plan/slices/167-no-test-device-counts.md)
**Session id and playback events (Slice 250).** Dino counts carry an optional `session` (32 lower-case hex digits, random, made at each cold start, kept in memory and on disk only inside unsent queued counts, never reused for a later launch or tied to an install, device or person) and `seq` (order inside the session, from 1). `dino_usage` columns: `blob16` = session (empty when none), `double2` = seq (-1 when none); `blob9` = detail, `double1` = sampling weight (still `SUM(double1)`). A malformed `session` or `seq` is dropped from the row, never the event; a `seq` without a valid session is dropped too. Sampling is decided once per session by the app, so a session is complete or absent. New names `read_started`, `read_paused`, `read_resumed`, `book_left` (no detail) and `read_stopped` (detail one of `left_book`, `finished`, `cancelled`, `language_changed`, `restarted`, `window_stopped`, `skipped`, `failed`, `other`; `window_stopped` is accepted but not emitted yet). Analytics Engine allows 20 blobs and 20 doubles per point (`dino_usage` now uses blobs 1-20 and `double1`-`double6`; the full column map is in the Slice 351 and 352 paragraphs below). **One session in order** (the `analytics-query` agent's column map gains `session` and `seq`; name the dataset, `dino_usage` for production): `SELECT double2 AS seq, blob1 AS name, blob2 AS book, blob9 AS detail, timestamp FROM dino_usage WHERE blob16 = '<32 hex>' ORDER BY double2`. Timestamp is the batch's send time, so order by `seq`, never by timestamp. A playback bug shows as `book_left`, then no `read_stopped`, then `read_resumed`/`read_paused` while another book is open. A crash or user report holds the same id (`session` in the stored JSON; `pull-crashes.mjs` prints it), so a reported code leads to that session's rows. (Slice 250: docs/plan/slices/250-dino-playback-events-and-session-id.md)
**Who and when on every Dino row (Slice 351).** Every count may carry `uiLang` (one of the 15 app languages, `READING_LANGUAGES`) = `blob17`, `installAge` (`first`, `d0`, `d1_7`, `d8_30`, `d31_plus`) = `blob18`, `launchNo` (`1`, `2_5`, `6_20`, `21_plus`) = `blob19` and `sinceLaunch` (whole seconds since the launch started, 0-86400) = `double6`; a missing or invalid one is stored `none` / -1 and keeps the event. The app works the two buckets out from a first-launch day and a launch count kept only in local preferences and never sent (no install id); a Core test keeps the lists equal. `blob20` is the screen (Slice 352, next paragraph). Order a session by `double6` then `double2`, never by timestamp. Speaker rows (Sonos, Alexa) carry `none`/-1. The `premade_audio` fallback reasons also split by cause (`no_pack`, `pack_failed`, `text_mismatch`, `no_clip`, `file_missing`; `clip_missing` is the older catch-all), a reading fallback names its book, and `speech:animal_clip_unplayable` became `animal_clip_copy_failed` / `animal_clip_play_failed` (old builds still send the old one). Queries: `docs/analytics/dino-session-queries.md`. (Slice 351: docs/plan/slices/351-dino-usage-context-and-audio-causes.md)
**Screens, taps, settings and read origins (Slice 352, Dino).** `blob20` = the screen the count was made on (one of `SCREENS`, else `none`: an older build, or a count before any page) on every row, so a download or a fallback says where it happened. `dino_usage` is now full on blobs (1-20) and uses `double1`-`double6`. New events, all about no book (book and source `none`, language `und`), and all behind `telemetry.enabled`, the grown-up's switch and the production-build gate like every count: `screen` (detail `<screen>:<action>`, actions `shown|next|back|skip|close`), `tap` (detail `<screen>:<control>`, one flat `CONTROLS` list, never which key, language, author or book), `setting_changed` (detail `<setting>:<value>`, `SETTING_VALUES`: a switch `on|off`, `reading_speed` a `slow|normal|fast` bucket, `reading_mode` `text|picture|picture_text`, `app_language` one of the 15; the usage switch only ever reports `on`, because turning it off clears the queue), `app_backgrounded` and `app_resumed` (detail = the screen, or `none`). **Read origin:** `book_opened` and `read_started` carry `wizard|shelf|corner|resume|next_book` as their `detail` (empty for a build before the slice; `resume` and `next_book` are accepted, but no path in the app emits them yet). The stats rollup (`worker/stats*.ts`) is unchanged: it reads `blob1`, `blob2`, `blob7`, `blob12` and `double1`/`double5` and `blob9` only for `store_download`, `book_listened`, `read_paused` and `read_stopped`, never for `book_opened` or `read_started`, so a detail on those two cannot change a rollup filter or total, and `blob20` is a column it never selects. The lists in `events.ts` (`SCREENS`, `SCREEN_ACTIONS`, `CONTROLS`, `SETTINGS`, `SPEED_BUCKETS`, `READING_MODES`, `READ_ORIGINS`) must equal the app's `UiScreens`, `UiScreenActions`, `UiControls`, `UiSettings`, `ReadOrigins` in `DinoReader.Core/UiUsage.cs`: `UiUsageTests` compares them. The app sends in batches of 40 (`UsageBatch.FlushAt`) and sends at once when 40 wait, so a busy session never meets the 50-count / 32 KB cap. `SilentButtonGuardTests` fails when a press in `src/Dino/DinoReader.App` is not counted (`UiUsage.Tap`, `Taps.AddTap(view, handler, UiControls.X)`, `UiUsage.Counted`) or marked `// no-tap-count: <reason>`; its baseline `tests/Dino/DinoReader.Tests/SilentButtonBaseline.txt` may only go down. Queries: `docs/analytics/dino-session-queries.md`, timelines with `tools/usage-sessions`. (Slice 352: docs/plan/slices/352-dino-screen-and-tap-events.md)
**Beta dataset (Slice 251).** A Dino iOS TestFlight or App Review build (`UsageEligibility.ChannelOf`, `UsageGate.Channel`; only Dino sets `SendsBeta`, RTST and crash reports keep the old yes/no) posts its counts to its own route `POST /api/events/beta` (`BETA_EVENTS_PATH`, also `/dino/api/events/beta`, in `run_worker_first` of both wrangler configs), which `worker/events.ts` writes only to `DINO_USAGE_BETA` (dataset `dino_usage_beta`, declared in both configs; it needs no `DINO_USAGE`, without it a 503). The production route `/api/events` writes only `DINO_USAGE` and answers 400 to a body with `channel: "beta"`. An older or rolled-back Worker has no beta route and answers 404, which the app drops, so beta rows can never land in `dino_usage` (no field to ignore). RTST answers the beta path 404. `dino_usage_beta` holds App Review traffic as well as testers'. Never mix the two in a report: the `analytics-query` agent names the dataset it reads, and production questions read `dino_usage` only. Android: no way to tell a Play testing track from production on the device (see the slice file). (Slice 251: docs/plan/slices/251-dino-beta-usage-dataset.md)
Robot and own-machine exclusion lives in `UsageEligibility.IsEmulatorBuild`, `UsageGate` and the `worker/events.ts` arch drop (Android/iOS `x64`/`x86`); every test harness must set the off switch (env `READTHESTUPIDTEXT_NO_USAGE=1`, or the Android `no-usage` marker file). (Slice 179: docs/plan/slices/179-no-robot-or-own-machine-counts.md)
**Listens and listening time (Slice 288, Dino).** `book_listened` (book, language, no detail) is sent once per reading, when played time reaches 30 s; a listen = `COUNT`/`SUM(double1)` of `blob1 = 'book_listened'`. `seconds` (integer 0-86400, else dropped from the row, not the event; kept only on `read_paused` and `read_stopped`, which always send it; an app's `book_listened` sends none and `/api/events` ignores one; only a speaker platform's row, Slice 289, platform `sonos`, detail `estimated`, carries an estimated `seconds`) is `double5` (-1 when none), the whole seconds of audio heard since the previous paused/stopped row of that reading (0 allowed). **Hours = `SUM(double1 * double5) / 3600` over `blob1 IN ('read_paused','read_stopped')` with `double5 >= 0`**; counted from the release that ships Slice 288 on, older builds send none. Always filter on `blob1` and exclude speaker rows (`blob7 <> 'sonos'`): `double5` is -1 for every other event, and a Sonos `book_listened` holds the book's length in it. (Slice 288: docs/plan/slices/288-dino-listens-and-listening-time.md)

Query counts through the Analytics Engine API with the read-only token `CF_ANALYTICS_READ_TOKEN` in `D:\secrets` (`analytics-query` agent); Dino `blob10-15` / RTST `blob18-20` + `double2-3` hold country and device buckets. (Slice 166: docs/plan/slices/166-usage-device-context.md)
The `fallback` count (Slice 273, both apps): a feature fell back to something else. Dino: `detail` is `<area>:<reason>` from `FALLBACK_AREAS` x `FALLBACK_REASONS` (`worker/events.ts`; the apps' `FallbackArea`/`FallbackReason` in `Application/Usage/FallbackKind.cs` must be the same lists, a test in each suite compares them), about a book or no book, and the optional whole numbers `count` (times this session; for `read_voice` the pieces read by clips) and `deviceCount` (pieces read by the device voice) are `double3`/`double4` (-1 for none; a malformed one is dropped from the row, not the event). `read_voice` is `premade` only when every spoken piece had a clip, `partial` when some fell back; a read of a book with no pack published (an own book, or no pack in that language, `device:no_pack`) is a `read_voice` but never a `fallback`. **Once per session with a count:** the first occurrence of each (area, reason, book, language) in a session is sent at once with `count` 1; if it happened again, one more row with the session total is sent at each usage flush (book left, app stop or sleep, start-up) when the count grew since the last row, so a session can have several rows, never one at session end only; `FallbackTally`, shared by both apps. **Queries take `MAX(double3)` per session (`blob16`) + area + reason, and always filter on `blob1` (the event name)**, because `double3`/`double4` mean different things per event: `fallback`: `double3` = times this session, `double4` = none (-1); `read_voice`: `double3` = pieces read by clips, `double4` = pieces read by the device voice; other events: -1. The fallback reason of a `partial` read is `text_mismatch` or `clip_missing`, whichever caused more of its misses (a tie says `text_mismatch`). RTST has all 20 blobs in use, so its `fallbackArea` and `fallbackReason` are stored in the `stage` and `outcome` blobs (a fallback carries neither; every RTST query filters on the event name, and a test keeps the area and reason lists from ever equalling a stage or outcome) and `count` is `double4` there (RTST's `double3` is not the count), so name the dataset in every query. New areas and reasons are appended to the two lists inside the part that adds them; never free text, a file name or book text. Part B adds the areas `speech` and `translation` (shared code reports through `IFallbackSink` in `Application/Usage`; RTST answers with `FallbackReporter`, Dino with `DinoFallbackSink` as a count about no book). Part C adds the areas `pack`, `ocr`, `document`, `store`, `config` and `ui_language` (reasons in the `FallbackKind.cs` block "Part C"). Part D adds the areas `window`, `font` and `library` and reasons for the swallowed-catch class (block "Part D"); a catch that is not a fallback carries `// no-fallback: <reason>` on the line after its opening brace (Slice 273 part D). **A config fallback is reported through a sink that only queues a count, never from the usage sender's send path and never by fetching the config**, so it cannot loop; with no config held (telemetry still off by default) a `config_default` count is dropped by the same gate as every other count.
The Dino host also serves the free story store (Slice 92): `GET /api/stories`, `/api/stories/<id>/cover` and `/api/stories/<id>/download[?v=n]` (`worker/stories.ts`, Dino only; `/api/stories` and `/api/stories/*` plus their `/dino` twins are in `run_worker_first`). Every Dino book (starter or store) is a folder `content/dino/<stem>/` (`story.md`, `book.json` with the id, version, ages, author, credits, colour, voices and content hash, `pictures/`, `cover.jpg`, `cover-thumb.jpg`, `translations/`, `art.md`); `dotnet run --project tools/dino/DinoReader.BookBuilder -- build` writes `artifacts/store/<id>/` and the committed starters, `check` fails when a STARTER changed without `stamp` (which raises its version; a store book needs none, Slice 239: `publish-store` versions it from its content hash and delists a story whose folder is gone) and runs in CI (Slice 157, Decision 162: docs/plan/slices/157-dino-book-content-out-of-tests.md). Store stories are built with `build` (to `artifacts/store/<id>/`) and uploaded **automatically on every merge** by `dino-store.yml`'s `publish-store` job (the `dinostore` target; every book whose content hash differs from the live one, as live + 1; Slice 158, 239, Decision 163); `tools/dino/upload-store-story.ps1 <id>` is the manual fallback. Either way the files go to `dinoreader/stories/<id>/{meta.json, cover.jpg, story-v<n>.dino}` in the downloads bucket, `meta.json` last: a folder is listed only with `meta.json` and a package, and `meta.json` carries `schemaVersion` (the `.dino` format), `title`, `language`, `pageCount`, `minutes`, optional `version`/`added`/`credits`/`creditsByLanguage` (language code to credit line, all 14 non-English languages per book, capped like `credits`; the card shows the app language's else `credits`; `check` enforces it; not in `BookHash`, so editing never bumps a version; Slice 192: docs/plan/slices/192-dino-store-credits-in-every-language.md), `ageMin`/`ageMax` (both or neither; integers 0-18, min <= max, else both dropped) and `author` (trimmed, max 100; Slice 112) (`worker/stories.ts` trims `credits` and caps it at 200 characters; Slice 102). The story id is the package id; upload a new `story-v<n+1>.dino` rather than overwriting a version (`?v=` is cached for a day).
A store book may also have an **audio pack per language** (Slice 246 B2): `audio-<lang>-v<n>.zip` in the same folder, listed in `meta.json` as `"audio": {"<lang>": {"version": n, "bytes": b}}` (written by `BookBuilder build-audio`, which keeps the version in the book's `audio-cast.json`; the list item gets `audio` with a `url`). `GET /api/stories/<id>/audio/<lang>?v=<n>` serves the zip (immutable, cached a day) only when meta lists that language at that exact version AND the zip is in the folder; a missing, wrong or unlisted `?v=`/language is a 404, and a listed pack nobody uploaded is simply not offered. Upload packs before `meta.json` (`tools/dino/upload-store-story.ps1` does); never overwrite a version. Old app builds never ask. The route also serves the version one behind the listing (so a phone with a slightly old listing gets no 404), which is why `publish-store-books.mjs` never deletes old pack versions (Slice 360: docs/plan/slices/360-dino-play-waits-for-wifi.md). Tests: `worker/stories-audio.test.mjs`.
Each pack may also have a **listening track for smart speakers** (Slice 281): `listen-<lang>-v<n>.m4a` (AAC, the pack's clips joined in read order, built by `BookBuilder build-listen`), listed as `listenSeconds` in the pack's `meta.json` `audio.<lang>` entry; the list item then carries `listenUrl` (`/api/stories/<id>/listen/<lang>?v=<n>`) and `listenSeconds`. The route serves `audio/mp4` inline with Range, HEAD and conditional support (the same `serveObject` as the zip) and answers 404 unless meta lists that language at that exact version with `listenSeconds` AND the .m4a is in the folder (a listed length without the file is dropped from the offer). No auth, and no usage count for plays (closed event list). Tests: `worker/stories-listen.test.mjs`. (Slice 281: docs/plan/slices/281-dino-listening-tracks.md)
**Error answers of the story routes (Slice 357).** Only a **400** carries a body (`badRequest(message)` in `worker/stories.ts`: `{"message": "<English sentence>"}`, shown by the app as it is; no story route answers 400 today, a malformed id or `?v=` is a 404, so the helper is there, tested, for the first route that validates input a person can fix); every other error (402 no proof, 403 purchase not valid, 404, 429, 503) is the status alone with no body, and the app supplies the translated text for it (`HttpErrorClassifier`, Application/Net). A store that cannot be asked (a missing store secret, an outage) is **503**, not 403. Never put a code slug or a sentence in a non-400 body. The one remaining slug is `ServedFile.unavailable` (downloads.ts, the 502 for a listed file missing from the bucket). (Slice 357: docs/plan/slices/357-server-error-messages.md)

The Dino host also answers an anonymous **Sonos music service** (Slice 283): `POST /sonos` (and `/dino/sonos`, both in `run_worker_first`; `worker/sonos.ts` + `sonos-soap.ts`, SOAP by hand, any other method 405). Its catalogue is the `/api/stories` list read through `handleStories` (only a book with `listenUrl` in a language appears, under that language; the root lists languages in their own names, a language lists its books as one playable `audio/mp4` track each, ids `lang:<code>` and `track:<code>:<storyId>`); `getLastUpdate`'s `catalog` is a hash of the offered tracks. Every failure is a SOAP fault with HTTP 500 (`Client.ItemNotFound` for an unknown id). No household or account state, the credentials header is ignored, and nothing is logged (no ids, titles or faults). Tests: `worker/sonos.test.mjs`. (Slice 283: docs/plan/slices/283-dino-sonos-music-service.md)
**Speaker plays are counted at `getMediaURI`, never on the audio route (Slice 289).** Sonos asks for a track's URI once per play, while a speaker fetches the one `.m4a` in several Range requests, so counting fetches would over-count. `worker/speaker-usage.ts` (platform-neutral: the caller names the platform; Slice 282's Alexa reuses it) writes one `book_listened` row to `DINO_USAGE` through the shared `toDataPoint` in `events.ts`: platform `sonos`, source `shelf`, book id, language, `double1` 1 (no sampling), `double5` = the track's `listenSeconds`, `blob9` detail `estimated`, version, session and device blobs empty, country from Cloudflare. It never goes through `/api/events` (whose platforms stay android/ios/windows) and is off when `telemetry.enabled` is false in `dinoreader/config.json` (`index.ts` passes the same check). A speaker row has no downloads and its seconds are an estimate (the length, not played time), so hours = `SUM(double1 * double5)` over `blob1 = 'book_listened' AND blob7 = 'sonos'`, never mixed into the apps' `read_paused`/`read_stopped` hours. Tests: `worker/speaker-usage.test.mjs`, `worker/sonos.test.mjs`. (Slice 289: docs/plan/slices/289-dino-count-sonos-plays.md)
The Dino host also answers an anonymous **Alexa kid skill** (Slice 282): `POST /alexa` (and `/dino/alexa`, both in `run_worker_first`; `worker/alexa.ts` handlers, `alexa-verify.ts` request checks, `alexa-roots.ts` trusted roots; package in `alexa/skill-package/`, English only, en-GB and en-US, AudioPlayer, marked child-directed). **No server state:** every `AudioPlayer.Play` carries the token `v1|<book>|<lang>|<version>|<segmentStartMs>`, and pause, resume (a new Play at the offset Alexa sends), next, previous and start over read `context.AudioPlayer.token`/`offsetInMilliseconds`; a token is trusted only field by field after validation. Every request is checked first, any failure is a bare HTTP 400: certificate URL rules, the chain (fetched once per URL per isolate, leaf valid and named `echo-api.amazon.com`, ends at a root in `alexa-roots.ts`: Amazon Root CA 1 and Starfield Services G2, from Amazon's live chain 2026-11-07; extend the list if Amazon's chain moves), `Signature-256` over the raw body, 150 s timestamp, and `ALEXA_SKILL_ID` (a `vars` entry in both wrangler configs; **fail closed: while it is empty every request gets 400**, since the signature only proves the sender is Alexa, not our skill; once the skill exists its id goes into both wrangler configs by a PR, never into the dashboard, because every deploy overwrites a dashboard value with the config's). The chain cache is keyed by origin+path (no query), size-capped; request and chain bodies are read with a running byte cap; PlaybackController answers carry AudioPlayer directives only (no speech, no `shouldEndSession`). The X.509 reading is a minimal DER reader, no dependency: `@peculiar/x509` needs a reflect polyfill under node and under wrangler. **Counting:** one `book_listened` row per played segment, platform `alexa`, written on `PlaybackStopped`/`PlaybackFinished` (seconds = event offset minus the token's start, detail `reported`; no offset = the book's remaining length, detail `estimated`), so a paused-and-resumed book makes two rows (nothing joins them, like the `blob7` rows above). Hours: `SUM(double1 * double5) / 3600` over `blob1 = 'book_listened' AND blob7 = 'alexa'`, never mixed with the apps' `read_*` hours. No household, user, device or skill-instance id is stored and nothing is logged. Tests (offline, with a test CA built in the file): `worker/alexa.test.mjs`. (Slice 282: docs/plan/slices/282-dino-alexa-kid-skill.md)

Switched by `crashReports.enabled` in each config object (`dinoreader/config.json`, `readthestupidtext/config.json`; default off, missing = off, read through the same 60 s cache as `telemetry`): never set it to true before the Play Data safety "Crash logs" and App Store "Crash Data" forms are saved (`STORE.md`, Slice 227 item 8). The user's exception to the production-only rule (2026-10-31): **TestFlight installs send crash reports**, tagged `testflight`, and stay out of the usage counts; debug builds, unstamped versions, emulators, Firebase Test Lab, robots (the Worker drops Android/iOS `x64`/`x86` too) and the harness off switch still send nothing (`CrashEligibility` beside `UsageEligibility`). Validation helpers are shared with `events.ts`, not copied. Retention: the Worker never deletes, so an R2 lifecycle rule on the `crashes/` prefix (delete after 90 days, `wrangler r2 bucket lifecycle add readthestupidtext-downloads crash-reports-90d crashes/ --expire-days 90`) is set on the bucket (added 2026-10-31; keep it if the bucket's rules are ever changed; the privacy text says reports are kept only as long as needed); the abuse limits are the per-connection `CRASH_LIMITER` and the 64 KB body cap, with no global cap. `testflight` is accepted only for platform `ios`, and nothing authenticates the sender, so treat the stored reports as untrusted data. A crash report holds no user text: log calls must never carry typed or read text, book titles or file names (the rolling log's tail goes out with the report).
