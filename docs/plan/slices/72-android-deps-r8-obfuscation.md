## Goal

Google Play flagged release 1.0.9 of Read The Stupid Text with **"DEX code optimization
is below our threshold — Obfuscation (1%)"**, fix by **Feb 2027**. Under 25% in any
category may cut visibility and publishing on Play. Both Android apps (Read The Stupid
Text, `uk.sirous.readthestupidtext`, and Dino Reader, `uk.sirous.dinoreader`) ship
with R8 off, so nothing is shrunk or obfuscated. This slice turns on R8 with
obfuscation in **Release builds only**, and in the same pass brings MAUI, the .NET for
Android workload and the AndroidX/Material packages up to their latest stable versions,
which the obfuscation setting needs and which also cut the deprecated edge-to-edge API
references Play reports (Slice 73).

## Findings (2026-10-21)

- No Android csproj sets `AndroidLinkTool`, `AndroidLinkMode`, `PublishTrimmed`,
  ProGuard files or a Release-specific property group. With `AndroidLinkTool` empty the
  build only dexes with D8: no shrinking, no obfuscation.
- Even with `AndroidLinkTool=r8`, the SDK's generated `proguard_xamarin.cfg` starts with
  `-dontobfuscate`. Obfuscation needs the newer property
  `AndroidR8ObfuscationMode=private-members` (keeps Java class names and public/protected
  members, renames private and package-private members, turns R8 optimisation on). It
  arrived in a .NET 10 servicing release and is the default from .NET 11. The workload
  installed locally (Android SDK 36.1.43) does **not** have it.
  Source: learn.microsoft.com/dotnet/android/building-apps/build-properties#androidr8obfuscationmode.
- Keep rules are generated by the SDK (`proguard_xamarin.cfg`,
  `proguard_project_references.cfg` from the Java types the assemblies use). Hand-written
  rules are needed only for Java reached by reflection.
- Play's metric only measures `classes*.dex`: the Android Callable Wrappers, MAUI's and
  AndroidX's Java code, the JNI glue. Our C# code lives in assemblies and isn't counted.
  So 25% is a target to **measure**, not a guarantee.
- `$(MauiVersion)` is referenced by all three projects and defined nowhere, so MAUI
  comes from whatever workload the machine has. CI installs `maui-android` unpinned on
  `dotnet-version: 10.0.x`; the iOS job pins workload set `10.0.401` because of Xcode.
- Versions on 2026-10-21 (local restore → latest stable on NuGet):

  | Package | Ours | Latest |
  | --- | --- | --- |
  | `Microsoft.Maui.Controls` | 10.0.20 (2025-12) | 10.0.120 (2026-10-21) |
  | `Microsoft.Android.Sdk.Windows` (workload) | 36.1.43 (2026-03) | 36.1.118 (2026-10-12) |
  | `Xamarin.AndroidX.AppCompat` | 1.7.1.4 | 1.8.0 |
  | `Xamarin.AndroidX.Fragment` | 1.8.9.3 | 1.9.0 |
  | `Xamarin.Google.Android.Material` | 1.12.0.5 (2025-08) | 1.14.0.6 |
  | `Xamarin.AndroidX.Activity` / `.Core` | 1.13.0.1 / 1.19.0.1 | already latest |

  The user chose **all to latest** (2026-10-21). Re-check NuGet when building and take
  whatever is latest stable then.

## Scope

- [ ] Pin `MauiVersion` to the latest stable MAUI 10 (10.0.120 or newer) in one place
      for all three projects (a root `Directory.Build.props`, or each csproj).
- [ ] Add direct `PackageReference`s at latest stable for AndroidX AppCompat, Fragment,
      Activity, Core and Google Material in the Android projects (`Mobile.Shared` if it
      covers both apps), so MAUI's older transitive versions are lifted. Resolve any
      NU1608/NU1605 downgrade or binding conflicts; if a version clashes with MAUI at
      runtime, back that one package off and say so in this file.
- [ ] Pin the Android workload in `android.yml` and `dinoreader-android.yml` to a workload
      set that has `AndroidR8ObfuscationMode` (Android SDK 36.1.118 or newer), with the
      matching `dotnet-version`, the way `ios.yml` pins its set. Update the local machine
      the same way (`dotnet workload update` / install that set) and note the command in
      `CLAUDE.md` via the `For CLAUDE.md` block.
- [ ] In a `Condition="'$(Configuration)'=='Release'"` group for both apps:
      `AndroidLinkTool=r8`, `AndroidR8ObfuscationMode=private-members`,
      `AndroidCreateProguardMappingFile=True`. Debug stays on D8, unchanged.
- [ ] Confirm the `.aab` carries `mapping.txt` (Play reads it from the bundle for
      de-obfuscated crash traces). The R2/sideload `.apk` needs none.
- [ ] Keep the iOS build green: MAUI is shared through `Mobile.Shared`. If the pinned
      MAUI needs a newer iOS SDK than workload set `10.0.401` / Xcode 26.6 provides,
      scope the pin to Android or bump `ios.yml` together, and record which.
- [ ] Keep the sherpa-onnx native packaging fix intact (check `lib/arm64-v8a/` in the
      built Release `.apk` per `CLAUDE.md`).
- [ ] Add `proguard.cfg` keep rules only for anything R8 actually strips (found by the
      smoke test), never pre-emptively.

## Done when

- Both apps' Release `.aab` and `.apk` build locally and in CI with R8 and
  `private-members` obfuscation; the build log shows R8, not D8-only.
- A Release build of each app passes a smoke test on the `RTST_Test` emulator via the
  `device-test` agent: launch, first-run language choice and voice-pack download, type
  text and read it, change speed and voice, camera/file → OCR → read (Read The Stupid
  Text), translation; Dino Reader gallery, grown-up gate, reading with per-character
  voices, cast screen.
- The iOS and Windows builds stay green.
- After the next Play release, the Play Console obfuscation percentage is recorded here.
  If it is still under 25%, that goes to *Outstanding work* with the measured number.
