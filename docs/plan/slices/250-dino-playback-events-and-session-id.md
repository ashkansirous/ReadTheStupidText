### Slice 250 — Dino usage: playback events and a session id that changes on every cold start

*In progress (wave 2026-11-04), draft PR.* After [Slice 249](249-dino-report-a-problem.md) (merged #781).

**Touches:** `src/DinoReader.App/Testing/DinoTestCommands.cs`, `src/ReadTheStupidText.Mobile.Shared/Crashes/CrashReporter*.cs`, `src/ReadTheStupidText.Mobile.Shared/Crashes/UserReport*.cs`, `src/DinoReader.App/ReportProblemPage.cs`, `tools/crashes/pull-crashes*.mjs`, `tools/dino-usage-report.ps1`, `src/DinoReader.App/CLAUDE.md`, `src/DinoReader.Core/ReadStopReason.cs` (new), `src/DinoReader.App/TraceLines*.cs`, `src/DinoReader.App/MauiProgram.cs`, `src/DinoReader.Core/UsageEvent.cs`, `src/DinoReader.App/UsageCounter.cs`, `src/DinoReader.App/ReadingSession.cs`, `src/DinoReader.App/ReadingPage.xaml.cs`, `src/DinoReader.App/UsageSession*.cs` (new), `src/ReadTheStupidText.Application/Usage/UsageBatch.cs`, `src/ReadTheStupidText.Mobile.Shared/Usage/UsageQueueSender.cs`, `src/ReadTheStupidText.Application/Crashes/CrashReport.cs`, `worker/events.ts`, `worker/crashes.ts`, `worker/*.test.mjs`, `worker/CLAUDE.md`, `PRIVACY.md`, `site/privacy.html`, `site/dino/privacy.html`, `STORE.md`, `src/DinoReader.App/Platforms/iOS/Resources/PrivacyInfo.xcprivacy`, `tests/DinoReader.Tests/**`, `docs/plan/slices/250-dino-playback-events-and-session-id.md`

**Why.** The Slice 248 bug (iOS: leaving a book kept reading; the next book's Pause/Play drove the old one) could not be seen in the data: Dino counts only `book_opened` and `book_finished` (`UsageEvent.cs:9-27`), and rows cannot be tied together (no id of any kind, `UsageCounter.cs:10-11`, `PRIVACY.md:127-128`). With these events and a session id, that bug reads as "book left, no read stopped" followed by "read resumed" for the old book while a new one was open.

**Decisions locked with the user (2026-11-02).** "we should be able to record a sessionId. SessionIds would not be tied to a users, they'll get a new one on every cold start, so when the app is closed for a few minutes, we know that it is not the same session." So: a random id made at each cold start, kept only in memory, never stored across launches, never tied to the install, the device or a person. This replaces the "never an id" rule (`worker/CLAUDE.md:14`) for this one field; the rule is rewritten in this slice, not dropped.

**Design points added in planning (not user decisions; change them if they are wrong).**
- Each event carries its session id, so events queued in one session and sent in the next (the queue lives in Preferences, `UsageQueueSender.cs:42`) keep the session they happened in.
- Each event carries a sequence number within its session, because the stored timestamp is the send time of a batch and `day` is only the UTC date: without it the order inside a session is lost.
- Sampling is decided once per session, not per event (the remote config's sample rate), so a sampled session is complete and an unsampled one sends nothing.
- The session id also goes into crash reports and Slice 249's user reports, so a reported code leads to that session's usage rows.

**Claim design (coordinator, 2026-11-04, from a code read of origin/main).** `ReadingSession.Stop(string reason)` (`ReadingSession.cs:313`) already takes a trace string from `TraceLines.ReadingReason`; keep that trace text, and add a closed `ReadStopReason` enum (DinoReader.Core) that `Stop` takes, mapped to the trace text and to the usage Detail only at the boundary. Mapping of today's callers in `ReadingPage.xaml.cs`: LanguageChange (362) → `language_changed`; Superseded (579) → `restarted`; PageLeft (960) → `left_book`; User (1184, 1396) → `cancelled`, except a stop caused by the Windows window going away/closing → `window_stopped` (split the two at the call site; if neither is a window stop, `window_stopped` is not emitted); Skipped (1474) → `skipped` (new, added to the closed list); Other (918, `DinoTestCommands.cs:448`) → `other` (new). `finished` has no `Stop` caller: emit `read_stopped finished` where the read reaches its natural end. The Worker accepts exactly these eight reasons.

#### Work

- [ ] **1. The session (Android and iOS, Dino Windows head too since it shares the code).** `UsageSession`: a random 128-bit id (hex) and a sequence counter, made once per process start, in memory only. `UsageEvent` gains `Session` and `Seq`; `UsageCounter` fills them. Sampling per session as above. RTST mobile and Windows send no session field (unchanged; the field is optional on the wire).
- [ ] **2. Playback events.** New closed names in `UsageEventName` and the Worker's `EVENT_RULES` (`worker/events.ts:174-192`): `read_started`, `read_paused`, `read_resumed`, `read_stopped`, `book_left`. Each names its book (package id, "own" or "none", as today). `read_stopped`'s Detail is a closed reason, from the call sites of `ReadingSession.Stop` (`ReadingPage.xaml.cs` leave, window stop, Cancel, restart for a language change, a new read; confirm the list in code): `left_book`, `finished`, `cancelled`, `language_changed`, `restarted`, `window_stopped`. `Stop()` takes the reason (enum, stringified only at the usage boundary).
- [ ] **3. Worker.** `toDataPoint` (`worker/events.ts:296-306`) stores the session id in blob16 and the sequence number in double2 (check the Analytics Engine blob and double limits in Cloudflare's docs first; 15 blobs are used today). Validate the id's shape (32 hex) and the sequence (non-negative integer); drop the field, not the event, when it is malformed.
- [ ] **4. Crash and user reports** carry the session id (`CrashReport.cs`, `worker/crashes.ts`), so `pull-crashes.mjs` prints it and the analytics query for that session can be run from it.
- [ ] **5. Privacy text and store answers.** `PRIVACY.md:127-128` and both `site/` pages: say there is a random session id that is new every time the app starts, is not stored, and cannot tell two sessions of one person apart. `worker/CLAUDE.md:14`: the rule now reads "no id except the per-launch session id". Check the Play Data safety and App Store privacy definitions (via `web-research`) for whether a per-launch random id counts as an identifier, and update `STORE.md` and `PrivacyInfo.xcprivacy` to match; a console change is the user's step, in Outstanding work.
- [ ] **6. Reading it back.** The `analytics-query` agent's column map gains `session` and `seq`; add a short "one session in order" query to `worker/CLAUDE.md` or the query skill's notes.
- [ ] **7. Check.** Unit tests: one id per process, a new one on a new `UsageSession`, sequence increments, sampling per session, every `read_stopped` call site passes its reason. Worker tests: the new names and reasons are accepted, unknown ones dropped, a malformed session id dropped from the row. Emulator flow (Android) with the local test worker: play a book, Back, open another, Play; the worker test log shows `read_started`, `book_left`, `read_stopped left_book`, `book_opened`, `read_started` in sequence under one session id. The harnesses' off switch still keeps every real run out of production.
