Unit-test the margin choice; VM check: extend `dino-probe` logic into a permanent check, or assert it in an existing Dino VM check.
2. **Dino Windows head: R on the Record screen raises Windows' microphone consent prompt** (L33, `dino-record` key-R stage, 2 of 2 runs). `tools/desktop-vm/CLAUDE.md` says this stage passed in Slice 284 because the VM, which has no microphone, shows the app's own "Microphone is off" alert; now a `PickerHost` window "Let Dino Book Reader access your microphone?" takes focus and neither the Stop button nor an alert shows. If the app is right and the image changed, the check sets the guest's microphone consent for the test package before the stage and says so in `tools/desktop-vm/CLAUDE.md`. Either way, the app must show its alert, not stay silent, when consent is denied or pending.
3. **RTST highlight check finds no `SENTENCE` marker** (L264, S21, twice). The check types three sentences; the reader played CHUNK 1, 2 and 3 (one sentence each), so the highlight has no later sentence in a chunk to move to. Find whether the chunker now splits per sentence (then the check and `.maestro/rtst/sentence-highlight.yaml` need a text whose chunk holds two or more sentences) or the highlight is broken (then fix `ReaderPage`). Android and iOS share `ReaderPage`; one fix covers both.

## Causes (found before changing anything)

- **Item 2, cause: the check's premise was never true, the app is right.** The Slice 284 `dino-record` key-R stage was written but never run (`docs/plan/slices/284-...md`, Not yet verified: "never run"); the line in `tools/desktop-vm/CLAUDE.md` that "the VM has no microphone, so the alert is the usual outcome" was never observed. The app's capture call is unchanged since Slice 111: `MediaCapture.InitializeAsync` at `src/DinoReader.App/Platforms/Windows/RecordingAudio.windows.cs:20` with `<DeviceCapability Name="microphone" />` (`Platforms/Windows/Package.appxmanifest:80`); `git log` for both files shows nothing since Slice 279 touching that call. With no stored decision Windows asks the user on that first call (the `PickerHost` prompt) and the await waits for the answer; a refusal throws `UnauthorizedAccessException` which `RecordPage.TryStartRecorderAsync` (`RecordPage.cs:608`) turns into the "Microphone is off" alert. So the app shows its alert on denial and the OS prompt is the feedback while the decision is pending. Fixed on the check side: the stage writes `Deny` to the package's CapabilityAccessManager consent key before R and removes it after.
- **Item 3, cause: the check text, not the highlight.** Slice 214 (`eb30b1f7`, 2026-10-31) cut the first piece of a read to about 8 words (`SpeechTextChunker.ShortenFirstPiece`), and while the check types, the early start prepares the first two sentences as a head (`FirstChunkHints`, `AndroidSupertonicSpeechReader.cs:1548-1558`). With the old 142-character text that gives chunks of 42, 50 and 47 characters, one sentence unit each (logcat `hl-logcat.txt` lines 19733, 19826, 20375: "1 sentence(s)"), so `ReaderPage.ShowSentence` (`ReaderPage.xaml.cs:822`) never has a later sentence in a chunk to move to. Slice 190/213's text predates the cut. `HighlightCheckTextTests` reproduces the device's [1,1,1] for the old text and head. The highlight code was not changed.
- **Item 1** is as written in the slice: `GalleryPage.xaml.cs:534` chose `ReorderPhonePadding` on every platform.

## Design after the second strike

Reviews high 4/10 and medium 1/2 both found the Reorder padding wrong (rail: symmetric 316 dp; sideways: left used on both sides), after one patch to the formula. Not patched again: the layer no longer recomputes anything. `WindowShapeSeam.ShelfListGeometry` (src/DinoReader.Core/WindowShape.cs) returns one record, `ShelfGeometry(Left, Top, Right, Columns)`, the shelf list's real margins and column count; `GalleryPage.ApplyShape` computes it once, `ApplyShelfMargin` applies it to `StoryList.Margin`, and the Reorder layer gets the same record (`BesideRail(railWidth)` moves Left onto the page when a rail sits left of the list) through `ShelfReorderView.Open` / `Reshape`. `ShelfOrderGrid.Fit` takes a left and a right padding. The rail's 16 / 14 / 26 are `RailListInset` / `RailListTop` / `RailListRight`. `ReorderSidePadding`, `ShelfListLeft` and the page's `ReorderPhonePadding` / `ReorderTabletPadding` and rail-width columns are gone; columns are the shelf's own. Unit tests: phone, tablet upright, sideways, Windows no rail (narrow and wide), Windows rail, phone-class rail, sideways+tabletShelf, rail+sideways, and `BesideRail`.

Item 2 (second strike, VM run `reviews/s319-vm.md`): the registry `Deny` under `CapabilityAccessManager\ConsentStore\microphone` was NOT honoured for the MSIX app (the PickerHost prompt "Let Dino Book Reader access your microphone?" still took focus). The registry approach is removed entirely (the Set/Remove/Undo consent functions and the `RtstCheckRestore` marker). New `dino-record` key-R design: after R the stage waits up to 10 s for the system consent window (process `PickerHost`, or any top-level window whose name contains the English prompt text); if it appears, it finds the deny button by UIA (control type Button, Name from a list: "No", "Don't allow", "Deny", "Block"; the buttons it saw are logged) and invokes it; then it expects the app's "Microphone is off" alert (existing text match), dismisses it, and passes. No prompt appears (consent already decided): it expects the alert or the Stop button as before. A prompt with no findable deny button fails, naming the buttons seen. The detail names the path taken (prompt denied / no prompt). The stage changes nothing outside the app, so there is nothing to restore.

Review check2 #2 and #4: the Reorder layer's top inset is the shelf's `ShelfGeometry.Top` when it is set (the rail's 14), else the gap as before (`ShelfOrderGrid.Fit` takes a top padding); the layer applies the shelf's exact margins, and only the relayout decision in `Reshape` ignores changes below 1 dp.

Runtime change for the device check: on a non-Windows tablet or phone in grown-up mode the layer now uses the shelf list's padding (14, not the old 40 tablet padding) and the shelf's columns.

Third pass (reviews `s319-phone.md`, `s319-check3.md` #1, `s319-vm2.md`): (a) the highlight text is shortened from 263 to 223 characters because the S21 uiautomator dump clips text at 255 and `Assert-TypedTextShown` failed on it; same text in `highlight.ps1` and the Maestro flow, a test caps it at 240. (b) `ShelfReorderView.Reshape` always stores the new geometry and uses the whole-dp comparison only to decide whether to lay out again. (c) `dino-record` key-R: the consent wait is 20 s and keeps polling for the PickerHost window to the end (a Stop button no longer ends it); every FAIL of the stage ends with the consent path note, the top-level windows seen during the wait (name, process, buttons of windows outside Dino). Runtime change: the VM key-R stage takes up to 20 s instead of ending early when no prompt shows.
