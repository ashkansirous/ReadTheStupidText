## Why

The owner is about to publish three new books and Dino has no way to tell families about them. A cold start is when someone opens the app on purpose, so that is when the takeover shows. Slice 471 adds the push notification, and tapping it opens this same takeover.

## Decisions

Owner, 2026-11-28, this session (the earlier answers, kept):

- The takeover shows on a **cold start** (not on a resume) when the Store has books released after the family's **last Store visit**. It shows the covers of those books, **newest first**.
- **Once per batch** (owner: "once per batch. less nagging"). After it has been shown for a set of new books, it does not show again until a newer book is released. Opening the Store also counts as seeing them.
- **The last Store visit is saved every time the Store opens** (owner: "always save the latest time they opened the store in the app").
- **New installs** count the install time as a Store visit, so nothing shows on the first launch (owner: agreed).
- **Families who update the app** to this version get the update time as their last Store visit, as if they had just seen the Store (owner: "the ones that update the app, should see the update time as if they saw the shop"). Old books never show as new.
- Android, iOS and the Windows head all get it.

Owner, 2026-11-28, accepting the Claude Design mock (`docs/design/dino-reader/2026-11-28-new-books/`, README row "New books takeover", boards NB1-NB7 and the Shelf component), overriding the earlier banner decisions:

- **It is a full-screen takeover, not a banner on the kids' shelf** (the earlier "banner sits on the children's shelf and has a close button" is superseded: the mock supersedes this). Anyone who opens the app sees it; **showing it needs no grown-up lock**. Same trigger as above.
- **All its words are in the app's main language**: string keys in `Resources/Strings`, in every language the app ships (the 15 `AppResources*.resx` files).
- **Layout:** NEW tag, heading "A new book is here!" for one book or "<N> new books are here!", the line "Fresh in the Dino Store.", the covers with their titles (1: one big; 2: side by side; 3-4: two per row; 5: three on top, two below), then the button "See it in the Store" (1 book) or "See them in the Store" (2 or more), and an outlined "Back to books" button. **No x and no lock is drawn anywhere on the takeover.**
- **More than 5 new books:** the heading gives the real count, the 4 newest covers show, and the 5th spot is a "+N more" tile (N = count minus 4) with the caption "In the Store". The earlier "at most 5 covers" now reads: at most 5 spots.
- **"Back to books"** closes the takeover and goes to the kids' shelf, no lock.
- **The Store stays locked as today.** The "See it in the Store" button, a cover, or the "+N more" tile opens `GrownUpGate` first, then the Store with a **"Just arrived" group on top** (newest first, a NEW tag, a soft yellow edge on each row, see NB7), then the subscription card and "All books" as today. A cover tap scrolls the Store so that book is first. Nothing behind the takeover is reachable without the lock except the kids' shelf.
- The mock decides layout and words (*Claude Design* rule: the mock always trumps the plan).

Decided by this session (not the owner's words): the server already keeps a date-only `added` per book (`worker/stories.ts:133`, used for ordering at :429). A day is too coarse to compare with a visit time, so publishing also records the exact UTC time the book first went live. The slice keeps the flow name `new-books-banner` (referenced from `docs/plan/decisions.md` and `plan.md`); it tests the takeover.

## Work

- [ ] 1. **Release time on every book.** `publish-store-books.mjs` writes `addedAt` (ISO 8601 UTC) into `meta.json` the first time a book goes live, and never changes it on later versions. Books already live get a one-time backfill of their `added` date at 00:00 UTC, or the first `story-v1` upload time where there is no `added`. `worker/stories.ts` passes `addedAt` through on each `/api/stories` item (bump the cache key constant at :79) and orders by it after the tags. Add worker tests and extend `publish-store-books.test.mjs`.
- [ ] 2. **App reads it.** `StoreItem` (in `src/Dino/DinoReader.Core/StoreCatalog.cs`) gains `AddedAt` (nullable `DateTimeOffset`), and `StoreCatalog.Parse` reads it. A book with no `AddedAt` is never "new". Add tests in `StoreCatalogTests.cs`.
- [ ] 3. **The two saved times.** In `NewBooks/`, add named-constant `Preferences` keys: last Store visit, and newest release time already shown in a takeover. Opening `StorePage` writes the visit time. On the first launch of this version, the visit time is set to now, both on a new install and after an update (one "migrated" flag). Unit-test the rule "new = AddedAt > max(last visit, last shown)", newest first, plus the slot rule: up to 5 books show as covers; more than 5 gives 4 covers and a "+N" tile with N = total - 4 (a testable pure function, in `DinoReader.Core` if it has no MAUI types).
- [ ] 4. **The takeover page.** Add a full-screen `NewBooksPage` in `NewBooks/` built from the Design above: the header, the 1-5 slot layouts with the widths in the table, the "+N more" tile, the two buttons, and the accessibility labels. All words come from the new `NewBooks_*` keys, in all 15 resx files and `AppResources.cs`. Covers load from `CoverUrl` with the existing cover cache, and any wait over 500 ms shows a placeholder. No close control and no lock icon anywhere on it.
- [ ] 5. **Show it on cold start.** In `App.xaml.cs` (and `Platforms/Windows/App.xaml.cs` for the Windows head), after the catalog fetch that cold start already does (around :171), if there are new books, push the takeover over the kids' shelf (`GalleryPage`). Showing it saves "last shown". A failed fetch shows nothing. A resume never shows it. "Back to books" pops it back to the shelf with no lock.
- [ ] 6. **Taps and the Store.** The main button, a cover and the "+N more" tile call `GrownUpGate`; on a pass, open `StorePage` with the new books (newest first) and, for a cover, that book's id to scroll to. `StorePage.xaml` and `.xaml.cs` get the "Just arrived" group (NEW tag, label, rows with the `#FFD98A` inset edge) above the subscription card; the group is empty and hidden when there are no new books, and "All books" stays as today. If the gate fails or is cancelled, stay on the takeover. Expose an entry point "show the takeover for books since <time>" that ignores "last shown", for Slice 471's notification tap.
- [ ] 7. **Android, iOS and Windows.** The same behaviour on each head. The Windows head runs it the same way from its window start.
- [ ] 8. **Debug test hook and scripted flow.** A Debug-only hook (in `src/Dino/DinoReader.App/Testing/`, a new `DinoTestCommands.NewBooks.cs` in the style of the other files there) sets the two saved times and a fake catalog. Add the headless Maestro flow `.maestro/dino/new-books-banner.yaml` (name kept) with these cases: a cold start with 3 new books shows the takeover with 3 covers and no lock; the second cold start shows none; opening the Store clears them; a fresh install shows none; 7 new books shows 4 covers and "+3"; "Back to books" lands on the shelf with no lock; the main button and a cover tap show the lock, then the Store with "Just arrived" on top.
