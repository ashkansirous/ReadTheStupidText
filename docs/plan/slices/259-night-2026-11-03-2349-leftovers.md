#### For Slice 252 (item 5: run 41744435929, the signed Dino iOS step) (lifted 2026-11-04)

Read with `gh run view 41744435929 --json jobs` and `gh api repos/ashkansirous/ReadTheStupidText/actions/jobs/126294512284/logs`:

- Job `build-dinoios / build` ran 00:09:15Z to 01:40:07Z, step 9 "Release build (signed .ipa)" 00:10:06Z to 01:39:56Z (89 min 50 s), conclusion `cancelled`: the 90-minute `timeout-minutes` in `dinoreader-ios.yml:68` fired, nobody cancelled it. The RTST job of the same run (`build-ios`) succeeded in 52 min.
- The log goes silent after one line: `01:10:55.0237600Z Started external tool execution #181: /usr/bin/codesign -v --force --timestamp=none --sign 8471719C32EF44337655E42C075477639E7B2DAC .../DinoReader.App.app/Frameworks/TranslateMLKit.framework`. It is the first `codesign` of the build (the only `/usr/bin/codesign` line); the next line is `01:39:56 ##[error]The operation was canceled.`, then `Terminate orphan process: pid (16255) (codesign)`. So `codesign` hung for 29 minutes until the timeout.
- Likely cause (read from the logs and `.github/scripts/ios-signing.sh:23`, not reproduced): the keychain is made at `00:10:06Z` with `security set-keychain-settings -lut 3600` (lock after 3600 s), and the first `codesign` ran at 01:10:55, 1 h 0 min 49 s later. A build that reaches signing after an hour finds the keychain locked and `codesign` waits for a password prompt nobody can answer. The RTST build signed inside its hour (52 min total) and passed; this Dino build needed over an hour before the first signature (it normally takes about 50 min total). That also fits the earlier hang (run 41409120502, "silent after `IL stripping assemblies`", which is the step before the signing).
- Decision: the 90-minute limit stays (it did its job and freed the queue). The step needs a change: `ios-signing.sh` `set-keychain-settings -lut 3600` to a time longer than the job limit (21600), or `security unlock-keychain` again before the build. Done at build (Touches widened by the coordinator): `ios-signing.sh` now uses `set-keychain-settings -lut 21600` with a comment saying why; `bash -n` ok. If the next signed build still hangs, the keychain was not the cause.
