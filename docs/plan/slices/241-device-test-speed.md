Documented as the first step in `tools/phone/README.md` and `tools/CLAUDE.md`. Self-test: message and `-Reinstall` plan in `test-run-checks.ps1`.
7. **Download stall logging.**
   - [x] Read: the Android/HTTP path (`MobileVoicePackService`, `StallGuardedRead`) already writes `stall`, `retry`, `done`, `failed`; the shared service is used on both platforms for the retry loop, but **iOS fetches the body through `IosBackgroundDownloader` (`IPackBodyFetcher`), which never goes through `StallGuardedRead`**: it only ended a transfer when the network was offline, so a stalled transfer with the network up never timed out. Fixed: `PackStallClock` (60 s with no byte, counted only over ticks taken while the app is active, the network is up and the watcher ran within 15 s of its last tick; any progress callback, a suspend/resume gap or a network blip gives a fresh 60 s; unit-tested in `PackStallWatchTests`) in the iOS watcher ends it as a `TimeoutException` (classified Failed, retried) after a `PACKDL stall` line. New `PACKDL progress pack=<id> bytes=<n>` every 5 s on both paths (`PackProgressLogGate`). Unit tests: `PackStallWatchTests`, `PackDownloadLogTests.ProgressLineHasTheDocumentedFormat`; the existing `BodyStallReportsPackAndTotalPositionIncludingTheResumeOffset` covers the Android read stall. iOS compiles (`net10.0-ios`).
   - [x] Phone check `pack-stall` (`tools/phone/checks/pack-stall.ps1`, `paused-notification.ps1 -Stall`) with the new Debug-only hook `stall-pack-network` (one use, lapses after 2 min unused, cleared when the download ends; Android: the next body read hangs and ignores its token, like a dead socket; iOS: the transfer's progress callbacks are ignored so the watcher sees no byte): asserts `PACKDL progress`, then `PACKDL stall ... phase=body` within 90 s of the hook, then a retry. Phone run 2026-11-01: `pack-stall` PASS (stall line 60 s after the hook, retry 24 ms later, pack restored).
   - The 7-minute silence on 2026-11-01 is **not explained**: the Android code has a 60 s stall guard and logs it; the likely causes are a build without the log sink (Release/old APK) or a path outside the guard (`destination.WriteAsync`, the headers phase or the throttle pause). The hook hangs the body read, a phase the guard already covered, so `pack-stall` proves the logging and retry, **not** the cause of the 2026-11-01 silence. The progress line makes the next occurrence readable.
8. **Brief rules.**
   - [x] `tools/CLAUDE.md` *Device-test brief rules*: no rerun of an identical failure, poll a download for growth and read PACKDL after 60 s, only `run-checks` / `run-flows` (no hand-picked `adb install`), redirect runner output to a file instead of `| tail`.
