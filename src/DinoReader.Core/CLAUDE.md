# CLAUDE.md — DinoReader.Core

- **DinoReader.Core** (`net10.0`, `src/DinoReader.Core`) — the pure dialogue library
  for Dino Reader: `StorySegmenter`, `SpeakerAttributor`, `GenderGuesser`,
  `VoiceCaster` (Decision 75). No package references; it references Application only for `LineReflow` (not Domain); voices come in as plain `VoiceOption(id, gender)`. Every language
  table lives in `LanguageRules` (`LanguageRules.English` today): a new language adds
  a rules instance and never touches the algorithms. Returns data only, no
  user-facing copy. Paragraphs are blank-line separated; a single newline is a
  sentence/segment boundary only where `LineReflow` (Application) says it is a real break, never on a bare newline (wrapped PDF/OCR text). (Slice 59: docs/plan/slices/59-dialogue-parser-voice-caster.md; Slice 76: docs/plan/slices/76-soft-line-break-reflow.md)
- `Story.BreakMap` uses geometry only when the included lines match the text. (Slice 79: docs/plan/slices/79-background-text-filtering.md)
- A story travels as a `.dino` zip (`StoryPackageWriter`/`StoryPackageReader`): `package.json` (`schemaVersion`), `story.json`, pictures, all top-level plain names. Import gives a new id and records the package's id as `Story.SourceId` (backup restore passes `keepId`); it refuses a newer schema, any entry name with a path part (zip-slip), and oversized entries, and `IStoryLibrary.ImportAsync` writes `story.json` last and removes the folder on failure. (Slice 91: docs/plan/slices/91-dino-story-packages-and-starters.md)
- `Story.Translations` (Slice 95) maps a language code to source piece text -> translated text, keyed by the exact attributed piece text `StoryTranslation` receives; it rides in `story.json` (package schema stays 1, the field is optional). Pieces must come from `StoryPieces.Split` (used by `StoryVoicing` and the builder) so keys cannot drift; lookups go through `BundledTranslations`. (Slice 95: docs/plan/slices/95-dino-translation-works.md)
- Picture + text books (Slice 98): `PictureTextBook` sorts pictures in natural file-name order (`1, 2, 10`), splits plain text on lines holding only `---` (CRLF or LF, surrounding spaces ignored; no such line means one page) and fills a page list's empty picture slots in that order. It has no mismatch result: a page without a picture reads as text. A picture + text page is just `ImageFile` + `Text` with no `Lines`: no new field and no `schemaVersion` bump. (Slice 98: docs/plan/slices/98-dino-picture-and-text-books.md)
- Every `AppLanguage` needs its own `LanguageRules` in `RuleSets` (a missing one silently falls back to English and finds no speakers), and every shipped book needs a translation table for every `UiLanguage.Supported` code; the coverage test reads that list, so adding a language fails the build until the tables exist. Engine codes that differ (ML Kit `no` for `nb`) are mapped in one named table in the adapter. (Slices 103, 105: docs/plan/slices/105-dino-nordic-dutch-books-and-rules.md)

Tests: `dotnet test tests/DinoReader.Tests/DinoReader.Tests.csproj` (xUnit v3, plain `net10.0`, any OS).
- A story has one cast per language (`Story.Cast` is the story language's, `Story.LanguageCasts` the others', keyed by `BundledTranslations.Key`); always use `CastIn`/`WithCastIn`, never read `Cast` for another language. Merges are the story's and shared. `story.json` `LanguageCasts` is optional (`schemaVersion` stays 1); a damaged language entry is dropped, not the story. (Slice 108: docs/plan/slices/108-dino-cast-per-reading-language.md)

- A character's flavour is `CastMember.Flavour` (the guess from `FlavourGuess` when the cast is built, or the grown-up's pick, pinned with `Edited`); null (older story) means guess from the name. Word lists live in `FlavourWords` and each language's `LanguageRules.Flavours`; a diminutive ("little", "baby") beats the animal word. `Storyteller` is the narrator's own flavour and is never guessed or offered. (Slice 113: docs/plan/slices/113-dino-character-flavours.md)
