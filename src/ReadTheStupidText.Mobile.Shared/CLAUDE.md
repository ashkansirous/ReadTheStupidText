# CLAUDE.md — Mobile.Shared

Shared platform code for every MAUI app here (RTST Mobile and Dino Reader). The namespace is
`ReadTheStupidText.Mobile.Shared` (Slice 131, Decision 134; project and folder names unchanged), so apps add
`using ReadTheStupidText.Mobile.Shared;`. `Platforms/Android` files stay in that namespace, never `...Platforms.Android`. The bare-`Application` and
sherpa-onnx gotchas in `src/ReadTheStupidText.Mobile/CLAUDE.md` apply to the `Platforms/` folders here too.
(Slice 131: docs/plan/slices/131-mobile-shared-namespace.md)

- Scanner/OCR stack (ML Kit, PaddleOCR, document scanner, PDF renderer, page-image keeper) lives in `Mobile.Shared/Platforms/Android`, registered once in `MobileSharedServices.Android.cs`; apps must not register their own and must forward `OnActivityResult` to `AndroidDocumentScanner.HandleActivityResult`. Positioned text uses `NormalizedRect` (0..1, top-left); `RangeToBoxMapper` maps story ranges to lines. (Slice 63: docs/plan/slices/63-positioned-text-extraction.md)
- OCR shared by Android and iOS is `Mobile.Shared/Ocr/` behind `IBuiltInTextRecognizer`. iOS ships its own `Microsoft.ML.OnnxRuntime` (sherpa's xcframework links it statically, no `OrtGetApiBase`). (Slice 55: docs/plan/slices/55-ios-batch9-features.md)
- **Translation is on both phones (Slice 160, reverses Slice 55 and Decision 148):** `MlKitTranslator` (`ITranslator` + `IModelPreparer` + `ITranslationPacks`) lives in `Platforms/Android` (`Xamarin.Google.MLKit.Translate`) and `Platforms/iOS` (`EngageSolutionsGroup.Apple.MLKitTranslate` 8.1.0, built for net9.0-ios18.0, embeds `TranslateMLKit.xcframework`), registered in each `MobileSharedServices.<OS>.cs`; same engine, languages, rules and errors, so keep the two files in step. iOS minimum is 15.5 (ML Kit's floor) in all three csprojs. Never add a service to one phone platform only: Android and iOS are the same app. (Slice 160: docs/plan/slices/160-ios-translation-parity.md)
- Windows (Slice 67) adds a `net10.0-windows10.0.19041.0` target on Windows hosts only (`-p:IncludeWindows=false` drops it): `Platforms/Windows` registers `WindowsPlatformServices` (Infrastructure's `SupertonicSpeechReader` behind `WindowsNeuralReader`, which maps its no-engine exception to ours, plus the WinRT `SpeechReader`), `Windows.Media.Ocr` boxes, a `Windows.Data.Pdf` renderer and the page image keeper. No scanner is registered. Packs live in `CacheDirectory` there, never `AppDataDirectory`. The project overrides a global `GenerateAppxPackageOnBuild` (`TreatAsLocalProperty`) because it is never an MSIX. (Slice 67: docs/plan/slices/67-dino-reader-ios-windows.md)
- OCR choice follows the page, never the app language: `LanguageImageTextExtractor` reads with the built-in recognizer first and a mostly-Latin result with at least `OcrPackChoice.MinLatinLetters` letters is final (a built-in failure falls through to the packs); any other page tries the installed non-Latin OCR packs via the pure `OcrPackChoice` (most own-script letters wins; stops at the first clear win; script/language table is `ScriptDetector`), and right-to-left ordering applies only when the winning pack's script is. The language argument is just a hint (pack order, pending-pack flag). Dino Reader shares this. (Slice 84: docs/plan/slices/84-ocr-follows-the-page-not-the-app-language.md)
- RTST image-text extractors return `ScanReadingText.From(...)` from `ExtractTextAsync` (geometry headings become blank-line breaks); `ExtractLinesAsync` stays raw for Dino. (Slice 86: docs/plan/slices/86-rtst-scan-line-geometry.md)
- Both apps' usage counts go through `Usage/UsageQueueSender` and `RemoteConfigClient`; Dino's `UsageCounter` and `AppConfigClient` only add their own `Record*` methods. (Slice 137: docs/plan/slices/137-rtst-phone-usage-counts.md)
- Every blocking wait in a MAUI app goes through `Waiting/WaitController` (500 ms gate, `WaitStage`/`WaitGate`); do not add a per-page spinner. (Slice 143: docs/plan/slices/143-shared-wait-overlay-dino-loading.md)
- Readers raise `ISpeechReader.StallChanged` through `StallReporter` (per-watch tickets, overlapping watches counted); wait usage is counted only through `WaitController.Finished`. (Slice 148: docs/plan/slices/148-phone-wait-followups.md)
- Device checks start as a Maestro flow (`.maestro/<app>/`, run with `tools/emulator/run-flows.ps1 -App rtst|dino`; README there). New screens get `AutomationId`s on the controls a flow touches (never find by text or position). State is reached through the Debug-only test hooks in `Testing/` (`TestHookDispatcher`; launch arguments, an Android broadcast, an iOS URL scheme) and checked through `RTST-TEST` logcat markers. Hooks and markers stay inside `#if DEBUG` and the csproj drops the folders in Release; the Android/iOS twins live in `Platforms/<OS>/Testing/`. An iOS app needs its `TestHooks.*.plist` imported (`Testing/TestHooks.props`). (Slice 162: docs/plan/slices/162-scripted-device-flows.md)
- Mobile.Shared `Testing`: launch-argument keys come only from `TestHookDispatcher.LaunchKeys`; never keep a key list in a platform file. (Slice 175: docs/plan/slices/175-test-gaps-permanent-checks.md)
- Warm-up state lives on the engine (`RefCountedTts` / `IosRefCountedTts`), never in a once-only reader flag: a flag spent on the Supertonic pack left the later Kokoro story voice cold. `WarmUp` must acquire through the same `AcquireEngine` a read uses; `EngineCache.Acquire(paths, forWarmUp)` must never evict an engine in use. Keep Android and iOS identical. (Slice 177: docs/plan/slices/177-dino-cold-start-synthesis.md)
- Resumable pack installers never track resume state themselves; they `Report` each run's end to `IPackResume`, which alone owns entries. (Slice 182: docs/plan/slices/182-pack-download-resumes-by-itself.md)
- Never call `StartForegroundService` for pack downloads. The keep-alive service starts only while the app is visible (plain `StartService`) and owns its own stop through the registry (`AndroidPackKeepAlive`, `PackDownloadService`); the app never calls `StopService`. The Debug marker file `throttle-pack-downloads` slows pack downloads to about 200 KB/s for device tests. (Slice 183: docs/plan/slices/183-pack-downloads-keep-going-when-locked.md)
- A notification Cancel of the voice pack saves `VoiceCancelHold` (owned by `VoicePackInstaller`); `OcrPackInstaller` must check it before installing and never start the scan pack for a held language. It lifts on any voice Ready and on a language change; never clear it elsewhere. Debug hook `cancel-pack-downloads` simulates the notification Cancel in scripted runs. (Slice 186: docs/plan/slices/186-no-ocr-download-after-voice-cancel.md)
- ML Kit translation model downloads go only through `TranslationModelDownloadSession`; never call `MlKitTranslator`'s download directly from a page. (Slice 187: docs/plan/slices/187-translation-download-waits-for-internet.md)
