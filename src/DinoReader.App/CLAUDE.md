- Dino translation (Slice 95): "my language" is the grown-up's picked language (`StoryTranslator.MyLanguage`, which reads `LanguageChoice.Current()`, the stored pick; never `CultureInfo.CurrentUICulture`, which only changes inside the picker's async flow). Each piece is looked up in the story's bundled `Story.Translations` first, then the on-device `ITranslator` (ML Kit on Android, from Mobile.Shared; none on Windows/iOS), then left as is. **Every book Dino ships (starters and every store upload) carries translations into all eight other languages** and `TranslateToMyLanguage = true`; the starter coverage test fails on any untranslated piece, so after editing a starter's text regenerate its tables in `content/dino/<stem>/translations/` before rebuilding. A store `.dino` is built the same way before it goes up to R2. (Slice 95: docs/plan/slices/95-dino-translation-works.md)
- Dino language rule (Slice 159, Decision 164): when the app language is X every word shown is in X. Strings come from `AppResources.Culture` (one static, set by `UiCulture.Apply` from the stored pick), never `CurrentUICulture`, which an async flow loses (that flipped the intro wizard to English after a Store round trip); number formats use `AppResources.Culture` too. `NoHardCodedUiTextTests` fails on a literal word in a text property or alert. Shipped books' titles (starters and store, English source) come from `ShippedTitles` (also what `meta.json`'s `titles` is built from; add a row for every new book, a test fails otherwise); the shelf shows `StoryTranslator.ShelfTitle`, the store `ShippedTitles.ShownInStore` (listing `titles`, then the table, then `title`). ## Story languages (Slice 173, Decision 168)
